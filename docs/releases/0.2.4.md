# GoOS 0.2.4

GoOS 0.2.4 adds symmetric multiprocessing and the concurrency work required to
use it in practice. All supported processors can run tasks, threads of one Linux
process execute in parallel, and independent kernel operations can proceed
concurrently instead of entering through a single global kernel lock.

The release also adds CPU affinity and per-CPU runtime statistics, improves
deadline handling, and hardens executable paging and SMP startup on KVM.

## Highlights

- All supported firmware-visible x86_64 processors, up to 64, start and join
  the scheduler.
- Every CPU has its own scheduler state, idle context, TSS, kernel-entry state,
  guarded stacks, and local APIC timer.
- Per-CPU run queues support migration, work stealing, remote wakeups, and
  reschedule IPIs.
- Linux threads of one process execute simultaneously on different CPUs.
- Cross-CPU TLB shootdown keeps address-space changes coherent.
- The old Big Kernel Lock is gone; native calls, Linux syscalls, faults, and
  housekeeping use explicit domain locks.
- Handle tables are locked per process, Linux compatibility state per family,
  and channels per channel.
- Native `TaskAffinity` and Linux `sched_setaffinity` / `sched_getaffinity`
  provide CPU-affinity control.
- The native `cpu` command exposes per-CPU load and scheduler/runtime counters.
- Deadline handling uses a fixed-capacity generation-safe index instead of
  scanning every waiter on each housekeeping tick.
- Static 7-Zip runs with real parallel execution on four CPUs.
- SMP is validated under KVM/Proxmox as well as QEMU TCG.
- AP startup initializes GDT accessed bits before secondary CPUs use the
  read-only mapping, fixing a KVM-only startup failure hidden by TCG.
- Executable paging drains replies whose requesting task disappeared,
  preventing abandoned page replies from filling the bounded paging channel.
- Race-detector host tests cover concurrency-sensitive scheduler, locking,
  deadline, handle, Linux, channel, and wait paths.

## Validation

The release validation covers:

- SMP on 1, 2, 4, and 8 processors;
- Linux ABI and process/thread workloads on 4 processors;
- repeated SMP and stress runs;
- static 7-Zip on 4 processors with matching extracted SHA-256 values;
- host race-detector coverage;
- KVM/Proxmox SMP and 7-Zip runs.

The SMP diagnostics verify concurrent kernel execution, not only parallel
userspace execution.

## Limits

- GoOS supports at most 64 processors and 64 scheduler Tasks.
- Device interrupts remain routed to the bootstrap processor, though they can
  wake Tasks on other CPUs.
- CPU hotplug, NUMA-aware placement, priority scheduling, and real-time
  scheduling are not implemented.
- Dynamic IRQ balancing is not implemented.
- Linux compatibility remains intentionally bounded; dynamic linking and a
  complete Linux ABI are not implemented.
- Some operations within one Linux family still serialize where shared family
  state requires it.
- Networking and an interactive Linux terminal remain future work.
