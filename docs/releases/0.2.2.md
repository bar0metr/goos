# GoOS 0.2.2

GoOS 0.2.2 runs the system from disk. The boot archive keeps only what starts
the machine and what recovers it; the shell, the configuration and log
services, the commands, and the Linux programs are installed on the FAT32
volume and published at `/system`. A machine whose volume is missing,
unreadable, or not an installed system of this release boots into recovery
mode instead, with the archive's own shell and a small set of commands.

```text
[MODE] normal
goos> ls /
tmp/
run/
bootstrap/
persist/
home/
state/
system/
apps/
goos> echo x > /system/motd
write: /system/motd: read-only filesystem
goos> fsck-fat --check auto
exec: cannot start fsck-fat: volume in use by the running system; check it in recovery mode
```

```text
[MODE] recovery: stage=record path=/system/release reason=release mismatch: installed 0.2.1, boot 0.2.2
goos> ls /bootstrap/bin
cat
cp
df
...
```

This is a compatibility check and a recovery path. It is not a verified boot
chain, an installer, or an update system.

## Highlights

- The archive is mounted read-only at `/bootstrap`. The installed system on
  the volume is published at `/system`, with `/system/bin`,
  `/system/services`, `/system/linux`, `/system/commands`, `/system/motd`,
  and the installation record `/system/release`; applications go in `/apps`
  and the user's commands in `/home/user/bin` (ADR 0175).
- PID 1 checks the installation record, the session service images, and the
  command index before it publishes anything, and prints the mode it chose.
  Recovery names the stage, the path, and the reason.
- The installed system cannot be changed by any client, through `/system`,
  `/persist/system`, a different spelling of the name, rename, replace, or a
  directory made where `/system` would be. The VFS enforces this on the
  directory's node, not on a path.
- A command gets grants only from the index of its own origin: the archive's
  for `/bootstrap/bin`, the installed one for `/system/bin`. A copy of a
  system command elsewhere gets its standard streams and nothing more.
- The shell searches `/system/bin` and then `/home/user/bin`; in recovery
  `/bootstrap/bin`. Linux programs keep `PATH=/system/linux`.
- The storage services restart from the archive. After a VFS, FAT32, or
  driver restart PID 1 attaches the volume again, restores the protection,
  and starts the session services from it once more. Storage that does not
  come back moves the system to recovery.
- `fsck-fat` checks the volume only in recovery mode; in normal mode it is
  refused as busy and nothing is unmounted.
- The archive shrinks to about 3.5 MiB in the validation build, of a 6 MiB
  limit that is unchanged.

## Implemented

### Boot and modes

- Bootstrap: PID 1, `vfs`, `block`, `virtio-blk`, and `fat32` start from the
  archive; PID 1 waits at most 20 seconds for the volume.
- Normal mode starts `config`, `log`, and `shell` from `/system/services`;
  the terminals stay in the archive.
- Recovery mode starts the terminals and the archive's shell, without
  configuration or logging. Its commands are `cat cp df echo edit fsck-fat ls
  mkdir mount mv pwd rm stat touch write`.
- Recovery stages: `forced`, `storage`, `record`, `services`, `index`,
  `publish`, `launch`, and `runtime`. Leaving normal mode stops the running
  shell before starting the recovery one and withdraws `/system` once nothing
  uses it. Returning to normal mode takes a reboot.
- A machine without a virtio-blk disk boots into recovery instead of
  stopping in the kernel.

### Installation record

- `/system/release`: `format`, `arch`, `release`, `startup`, `image`, and
  `index`, one each, at most 512 bytes. The format is read first and a
  format other than 1 is refused. The release must be the archive's own.

### Executables

- Origin by path: `/bootstrap/X` is an archive member launched by extent;
  everything else is a file-backed source. No file is looked for in the
  archive.
- PID 1 prepares services from the volume through the same bounded path as
  commands.
- The userspace runtime touches every page of a buffer before a native call,
  so a program read from a file can pass the kernel its constants.

### VFS

- Control protocol version 7: `Publish` and `Withdraw`.
- `/run` in the volatile root; `/bootstrap`, `/system`, and `/apps` reserved
  while nothing is mounted there.
- A reply to a client that has gone is dropped instead of ending the VFS.

### Build

- `make run` and `make run-gui` boot `build/goos-disk.img`, made from the
  build when it is missing and never changed when it exists.
- `make disk` installs a new disk and refuses an existing one;
  `make disk-overwrite` replaces it.
- `make system-image` builds the ISO and `system.img`.
- `make run RECOVERY=1` boots into recovery mode.
- `tools/sysimage` lays out the installed system; `mkfat32 -tree` copies a
  directory tree onto a volume in name order, and `mkfat32 -new` refuses an
  existing image.
- `LINUX_EXTRA` now adds programs to the installed `/system/linux`.

### Validation

- `make test-system-boot` (`tests/boot/system.sh`): the archive contents, a
  normal boot from disk, refused changes through every alias from native and
  Linux programs, persistence across a reboot, VFS, FAT32, and driver
  restarts, storage loss, forced recovery with a volume check, and recovery
  for a missing disk, a blank volume, a malformed record, an older release, a
  missing service image, and a malformed index.
- New validation faults: `fault driver` and `fault storage`.
- Every QEMU test boots a disposable installed disk.

## Upgrading a development disk

A disk made by 0.2.1, or by any build of another release, boots into
recovery with `reason=release mismatch` or `reason=no installed system on the
volume`. Nothing is changed on it. `make disk-overwrite` installs this
release over it, user data included; copy anything worth keeping off it
first, for example with `go run ./tools/mkfat32 -get`.

## Limits

- Programs read from the volume end when their storage fails; the shell
  comes back once the storage does.
- No installer, package manager, upgrade, rollback, or signature check. Anyone
  who can write the disk image outside GoOS can change the installed system.
- The installed release must match the boot archive exactly.
- One volume; no `/boot`, no self-booting disk.

[ADR 0175](../adr/0175-installed-system-and-recovery-boot.md) records the
design.
