# GoOS 0.2.0

GoOS 0.2.0 is the first Linux ABI release. Unmodified, statically linked
Linux x86_64 programs run as GoOS processes:

```text
goos> /system/linux/hello
hello from Linux ABI
goos> /system/linux/musl-hello one two
argc=3
hello from musl
goos> /system/linux/fsprobe /persist/demo.txt
write ok
read ok
stat ok
```

No CPU is emulated and no Linux kernel is present. The program's machine code
runs at ring 3, and a bounded layer in the kernel translates each Linux
system call into what a native GoOS process uses: VM regions, byte streams,
the kernel clocks, and one VFS session. A Linux process holds no authority a
native process with the same grants would lack, and it cannot reach the
native call gate at all.

## Highlights

- Static ELF64 `ET_EXEC` programs load lazily from their file and start on a
  System V stack with `argc`, `argv`, `envp`, and auxv.
- A dedicated `SYSCALL` entry with the Linux register convention and
  `-errno` results. Native programs keep `int 0x80`; each gate refuses the
  other's processes.
- 53 Linux system calls with real semantics; every other number returns
  `-ENOSYS` and is counted.
- Static musl programs run through the ordinary libc entry: TLS through
  `arch_prctl`, `malloc` on `brk` and `mmap`, stdio on `readv` and `writev`.
- Files, directories, status, and naming go through the process's VFS
  session, on the volatile root and on FAT32.
- A conformance probe prints the same lines on a Linux kernel and on GoOS.
- BusyBox applets run from a static BusyBox: `echo`, `pwd`, `cat`, `ls`,
  `mkdir`, `rm`, and more.
- Final VFS protocol version for this release: **13**.

## Implemented

### Process and entry

- Immutable `Native` and `LinuxX8664` process identity, set at validated
  launch (ADR 0132).
- `SYSCALL` entry through `IA32_LSTAR` with a guarded per-task kernel stack,
  sanitized RFLAGS, and an IRETQ return. The user stack is never a kernel
  stack.
- A static ELF64 parser and mapper with fixed bounds: 64 program headers, 16
  load segments, W^X, no executable stack, no `PT_INTERP` (ADR 0133).
- PID 1 classifies an executable by its magic; the kernel validates the
  format again. A Linux launch gets standard input, output, and error, one
  fresh VFS session, and the large resource profile, and nothing else
  (ADR 0136).

### System calls

- Memory: `brk`, anonymous private `mmap`, `munmap`, `mprotect`,
  `madvise(MADV_DONTNEED)`. No anonymous memory is executable.
- TLS: `arch_prctl(ARCH_SET_FS, ARCH_GET_FS)`, with FS base saved and
  restored on every context switch (ADR 0137).
- Files: `open`, `openat`, `close`, `read`, `write`, `readv`, `writev`,
  `lseek`, with `O_CREAT`, `O_EXCL`, `O_TRUNC`, `O_APPEND`, `O_DIRECTORY`,
  and `O_CLOEXEC` (ADR 0141, ADR 0144).
- Status: `stat`, `lstat`, `fstat`, `newfstatat`, `access`, `faccessat`,
  with a hand-laid-out `struct stat` (ADR 0142).
- Directories: `getdents64`, `getcwd`, `chdir`, `mkdir`, `rmdir`, `unlink`,
  `rename`, and their `*at` forms (ADR 0140, ADR 0143).
- Descriptors: `dup`, `dup2`, `dup3`, `fcntl`, `ioctl` (ADR 0146).
- Identity and time: `getpid`, `gettid`, `getppid`, the user and group
  calls, `uname`, `clock_gettime`, `nanosleep`, `prlimit64`,
  `set_tid_address` (ADR 0145).
- `exit` and `exit_group`.

[The ABI document](../architecture/linux-x86_64-abi.md) lists each call, its
status, its errors, and every difference from Linux.

### Translation

- Calls that wait use one continuation per task: the request is marked
  issued before it is sent, the task blocks in the scheduler, and a wake
  resumes the exact stage. Nothing polls (ADR 0134).
- One VFS session per process, the channel PID 1 granted. Every wait for the
  VFS has an eight-second deadline. A VFS that dies leaves the session dead;
  nothing reconnects it (ADR 0138).
- File bytes move through one 64 KiB memory object per process.
- A Linux path resolves in the GoOS namespace from a per-process working
  directory, in one bounded pass (ADR 0140).

### Hardening

- Every pointer goes through the checked copy helpers. Bad pointers are
  `EFAULT`; a transfer across the end of a mapping is short, as on Linux
  (ADR 0147).
- The descriptor table, the page quota, the directory records, the
  continuation table, and every copied structure have fixed bounds.
  Exhaustion is `EMFILE`, `ENFILE`, or `ENOMEM` at the call.
- A Linux program runs from `/system/linux` or from a writable volume. A
  call argument in a page of the image that is still loading waits for the
  page.
- The kernel counts refused calls, bad pointers, and VFS failures without
  logging per call.

### Validation

- `make test-linux-boot`: the release proofs, the hardening modes, two Linux
  processes at once, an I/O port fault, and Ctrl-C on a Linux process blocked
  three different ways, in one boot (ADR 0148).
- `make test-boot`: a Linux process through a VFS restart and through a late
  VFS answer.
- `make test-linux-reference`: the conformance probe on a Linux kernel.
- `make test-linux-busybox BUSYBOX=path`: six required applets of a BusyBox
  the caller supplies, and a report on others.
- `make test-linux-bench`: call times beside native cases.

## Native changes

- VFS protocol 12: a stat with a handle and no path describes that open
  file. Protocol 13: a stat and a directory entry carry the node's identity,
  which an open file keeps across a rename.
- The boot test no longer depends on where the shell prompt lands relative
  to a restarted service's marker.

Native programs, the native call ABI, and the native image format are
unchanged.

## Limits

This release runs x86_64, static, non-PIE programs. It has:

- no `PT_INTERP`, dynamic linker, or glibc;
- no `fork`, `vfork`, `clone`, or Linux `execve`;
- no threads and no `futex`;
- no signals: Ctrl-C ends the GoOS process and delivers no `SIGINT`;
- no pipes created by a Linux process and no `poll`;
- no networking;
- no `/proc`, `/sys`, or `/dev`;
- no file-backed `mmap` and no executable anonymous memory;
- no Linux ownership or permission enforcement and no root: every file and
  process shows user and group 1000, and mode bits are presentation;
- no terminal descriptor and no termios: a Linux program's output at the
  terminal is block-buffered by libc;
- no way to set a file time, so `touch` fails on an existing file.

BusyBox `sh` starts and runs builtins but cannot start a program. `nano`
does not run.

## Next

Process composition: `execve`, `pipe2`, `wait4`, a chosen `fork` semantics,
minimal signals, and `poll`, enough for BusyBox `sh`.
