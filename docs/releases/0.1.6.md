# GoOS 0.1.6

GoOS 0.1.6 adds its first full-screen native TUI application: a two-pane file
manager built entirely on the existing VFS and terminal architecture. The
release also introduces scoped raw terminal input, F1–F12 key sequences,
reusable terminal helpers, cursor addressing and a bounded ANSI colour subset
shared by the framebuffer and COM1 consoles.

## File manager

`gfm` opens two panels on the shell's working directory
([file manager](../userspace/file-manager.md)). The active panel is marked by
colour alone: bright frames, a highlighted title and a steel-blue selection;
there is no menu bar and no panel label. Panels are navigated with the arrows,
PageUp, PageDown, Home, End, Enter and Backspace, and Tab switches between
them. F5 copies the selected file to the other panel's directory, asking before
it overwrites; F6 moves or renames; F7 creates a directory; F8 deletes a file
or an empty directory after a confirmation; F2 reads both directories again;
F1 shows the keys; F10 quits.

Every failure is reported on the status line and the program carries on. Copy
streams through a 64 KiB shared buffer, so file size does not change its
memory use. Each panel holds at most 1024 entries and 64 KiB of names and says
so when a directory is larger. UTF-8 names, Cyrillic included, are kept byte
for byte; control bytes in names are displayed as `?`.

`gfm` is an ordinary command. It reaches files only through its VFS session,
reads keys on standard input and draws with ANSI output on standard output. It
holds no console, keyboard, framebuffer or I/O-port authority.

## Full-screen TUI support

The framebuffer terminal now parses up to eight CSI parameters and renders
absolute cursor positioning (`ESC[row;colH`, `ESC[nG`) and every erase variant
of `ESC[J` and `ESC[K`. A frame redraw addresses every row, so the manager never
scrolls the screen, and after the first frame only changed rows are sent.

`userspace/terminal` gives programs an allocation-free output builder for
cursor, erase and colour sequences, a key parser that turns bytes into key
events, and display-width helpers. `userspace/filemanager` holds the manager's
panels, dialogs and rendering behind a filesystem interface, so it is tested on
the host.

## Function keys

The PS/2 decoder now produces up to eight bytes per key. F1–F12 emit xterm
sequences (`ESC[11~` to `ESC[24~`, skipping 16 and 22), and Home, End, Insert,
Delete, PageUp and PageDown emit `ESC[H`, `ESC[F`, `ESC[2~`, `ESC[3~`,
`ESC[5~` and `ESC[6~`. IRQ1 passes the decoder an eight-byte buffer and
enqueues a sequence whole or not at all, so a full ring drops a key rather than
deliver a prefix of it. These sequences are part of the terminal input contract
([ADR 0124](../adr/0124-foreground-raw-terminal-mode-and-tui-input.md)).

## Terminal colours

The framebuffer terminal renders 16-colour SGR: reset, bold as bright,
foregrounds 30–37 and 90–97, backgrounds 40–47 and 100–107, and 39 and 49 for
the defaults, through one fixed palette in the terminal package. Erasing uses
the current background. Programs name ANSI colours, never RGB, so COM1 carries
the same byte stream and a host terminal shows the same screen in its own
palette.

## Raw terminal input

The terminal session protocol, `GTTY` version 3, adds raw mode. In it the
terminal service answers each read with the bytes typed, without echo or
editing, and relays output without redrawing the edited line around it. The
shell asks for raw mode only for a foreground system command whose manifest
declares the new `commands.GrantTerminal`, and returns to line mode as soon as
the job ends, whether it exited, crashed or was stopped. Leaving raw mode
resets colours and the cursor and clears the screen; so does a replaced session
or a restarted service. Ctrl-C still stops the foreground job. The shell also
asks for the framebuffer console's size and passes it to every command as
`COLUMNS` and `LINES`.

A terminal on COM1 has a size of its own and is resized silently, so `gfm`
asks it with a cursor position report (`ESC[6n`) at start, on F2 and once a
second while idle, and lays itself out on the smaller of the framebuffer and
that terminal. Shrinking the host terminal window shrinks the panels on both
consoles; on a serial-only console they follow the host terminal fully.

## VFS integration

`userspace/utility` gains filesystem calls that report their status instead of
ending the command — `Request`, `ReadDir`, `Stat`, `Mkdir`, `Rename`, `Unlink`
and a streaming, bounded `CopyFile` — for interactive programs, and
`TerminalSize`. `userspace/shell` gains `ValidName`, `JoinName`, `Parent` and
`BaseName`. A rename across two filesystems now answers `StatusUnsupported`
rather than `StatusInvalidArgument`, so a caller can tell the two apart.

The embedded Spleen subset gains the eleven light box-drawing glyphs the
manager's frames use, generated from the same upstream commit
([font provenance](../third-party-font.md)).

## Tests

- Host tests for every F key's make and break codes and exact sequence, the E0
  navigation keys and unknown extended codes.
- Framebuffer terminal tests for multi-parameter CSI, CUP, CHA, erase
  variants, all 32 foreground and background SGR codes, split and malformed
  sequences, unsupported attributes, glyph colours and padding guards.
- Key parser, output builder and width tests, including split sequences,
  alternate host-terminal sequences, malformed input recovery and zero
  allocation.
- TTY protocol and raw-input tests, and a VFS test for cross-mount rename.
- File manager tests against a model filesystem and a model terminal that fails
  on any write past a row or into the scrolling corner: sorting, movement,
  scrolling, refresh, every operation and its error paths, layout at several
  geometries, a too-small terminal and allocation-free rendering.
- `make test-console-gui` drives `gfm` through QEMU's PS/2 keyboard — help,
  navigation, mkdir and F10 — checks the markers raw mode and the shell leave,
  runs `ls` afterwards, then stops a second `gfm` with Ctrl-C and runs another
  command.

## Remaining limitations

- No embedded shell or command line inside the manager, no mouse, no viewer
  and no editor; F3 and F4 say so.
- No archive browsing and no plugin system.
- No recursive directory copy or delete, and no cross-filesystem move.
- No permission, ownership or symlink handling, no multiple selection, and no
  locale collation.
- No dates or free space in the panels: the VFS reports neither.
- The framebuffer shows ASCII, Russian Cyrillic and light box drawing; other
  characters appear as the replacement glyph.
- 16 ANSI colours only: no 256-colour or truecolour mode.
- With a framebuffer, a host terminal on COM1 larger than it does not enlarge
  the layout: both show the same screen.
- Output other processes write while the manager owns the screen lands on its
  display until F2 repaints; a program's last message before it exits is
  cleared with the screen.
