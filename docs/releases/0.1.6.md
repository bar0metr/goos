# GoOS 0.1.6

GoOS 0.1.6 adds `gfm`, a two-pane file manager and the first full-screen
program the system runs. To draw it, the release extends every layer under a
terminal: the keyboard decoder emits function keys, the framebuffer terminal
positions the cursor and renders 16 ANSI colours, the terminal service gains a
raw mode, and COM1 and the framebuffer become two consoles with a shell each.

## Two consoles

Up to 0.1.5 the kernel mirrored one byte stream to COM1 and the framebuffer and
merged both keyboards into one input ring, so one terminal service and one
shell served both screens. Line output survived that, because each screen wraps
text at its own width. A full-screen program addresses cells, and the two
screens have different numbers of them: the QEMU window has 106x33 at
1280x800, and a host terminal on COM1 has whatever its window has. One stream
could fill one screen and break the other.

0.1.6 splits them ([ADR 0125](../adr/0125-independent-serial-and-framebuffer-consoles.md)):

- The kernel adds two device objects. `SerialConsoleObject` writes to COM1 and
  reads the serial input ring; `GraphicalConsoleObject` writes to the
  framebuffer and reads the PS/2 input ring. Each ring counts its own Ctrl-C.
  `ConsoleRead`, `ConsoleInterrupt` and `WaitAny` accept these two objects
  alone.
- The logical console keeps writing to both screens for the kernel's warnings,
  PID 1's boot lines and the system services' reports. It has no input.
- PID 1 runs `tty` and `shell` on COM1, and `tty-fb` and `shell-fb` on the
  framebuffer when the machine has one. It keeps a `terminalSession` per pair
  with its own output stream, exec channel and exec page, tags each job with
  the shell that submitted it, and restarts each pair on its own.
- The boot test keeps driving the COM1 pair under the old names.

Typing in the QEMU window reaches `shell-fb`; typing in the terminal on COM1
reaches `shell`. `services` lists both pairs.

## File manager

`gfm` opens two panels on the shell's working directory
([file manager](../userspace/file-manager.md)). You move with the arrows,
PageUp, PageDown, Home and End, open directories with Enter, go up with
Backspace and switch panels with Tab. F5 copies the selected file into the
other panel's directory and asks before it overwrites one. F6 moves or renames
through an editable target path. F7 creates a directory, F8 deletes a file or
an empty directory after a confirmation, F2 reads both directories again, F1
lists the keys and F10 quits.

The active panel shows by colour: bright cyan frames, a teal title and a steel
blue selection bar, against grey on the other panel. The screen has no menu bar
and no panel labels. Directories show in yellow and files in light grey.

A failed operation prints its VFS reason in amber on the status line, such as
`Copy failed: read-only filesystem`, and the manager keeps running with its
panels intact. Copy streams through a 64 KiB shared buffer, so a file's size
does not change the memory `gfm` uses. Each panel holds up to 1024 entries and
64 KiB of names; a larger directory shows `+ entries, list truncated` on its
frame. `gfm` keeps UTF-8 names byte for byte and prints control bytes in names
as `?`, so a file name cannot send escape sequences to your terminal.

`gfm` fills the console you start it on. In the QEMU window it reads the
framebuffer's size from `COLUMNS` and `LINES`. On COM1 it asks your terminal
for its size at start, on F2 and after each idle second, so resizing the
window re-lays the panels within a second. Below 80x24 it shows a message
until the screen grows again.

After the first frame `gfm` sends only the rows that changed. Moving the
selection redraws two list rows and the lines that describe the selection.

`gfm` is an ordinary command. It holds its standard streams and a VFS session,
and no console, keyboard, framebuffer or I/O-port capability. The manager
itself lives in `userspace/filemanager` behind a filesystem interface, so its
tests run on the host against a model filesystem.

## Terminal output

The framebuffer terminal now parses up to eight CSI parameters of up to three
digits and drops longer or malformed sequences. It renders:

- cursor positioning: `ESC[row;colH`, `ESC[nG`, and the existing
  `ESC[nA/B/C/D`;
- erasing in the current background: `ESC[J`, `ESC[1J`, `ESC[2J`, `ESC[K`,
  `ESC[1K`, `ESC[2K`;
- colour: SGR 0, 1 (brightens the foreground), 22, 30-37, 39, 40-47, 49, 90-97
  and 100-107.

It skips the operands of SGR 38 and 48 and ignores other attributes and private
sequences such as `ESC[?25l`. Programs name ANSI colours; the framebuffer maps
them through one fixed 16-colour palette in the terminal package, and a host
terminal on COM1 uses its own palette. No application colour reaches the
kernel.

The embedded Spleen 12x24 subset gains the eleven light box-drawing glyphs
`─ │ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼`, generated by `tools/fontgen` from the same upstream
commit ([font provenance](../third-party-font.md)).

## Function keys

The PS/2 decoder emits up to eight bytes per key, where it emitted three. F1 to
F12 produce xterm sequences, `ESC[11~` to `ESC[24~` without 16 and 22, and
Home, End, Insert, Delete, PageUp and PageDown produce `ESC[H`, `ESC[F`,
`ESC[2~`, `ESC[3~`, `ESC[5~` and `ESC[6~`. Modifiers leave these sequences
unchanged.

The IRQ1 handler used to receive the bytes packed in one return register. It
now passes the decoder an eight-byte buffer, checks the keyboard ring's free
space, and enqueues the whole sequence or drops the key. A reader therefore
never receives a prefix such as `ESC[1`, which it would parse as other keys.
These sequences join the terminal input contract
([ADR 0124](../adr/0124-foreground-raw-terminal-mode-and-tui-input.md)).

## Raw terminal input

A full-screen program needs each key as you press it. The terminal service
session protocol, `GTTY` version 3, adds three requests:

- `RawMode` answers each read with the typed bytes as they arrive, with no
  echo and no line editing, and relays output without redrawing the edited
  line around it.
- `LineMode` returns to line editing and writes `ESC[0m ESC[?25h ESC[2J ESC[H`,
  which resets colours, shows the cursor and clears the screen.
- `Geometry` reports the console's columns and rows and whether they belong to
  the framebuffer.

The shell asks for raw mode for a foreground command of one stage whose
manifest in the system image declares the new `commands.GrantTerminal`, and
switches back as soon as the job ends: by exit, crash or Ctrl-C. A replaced
session and a restarted terminal service also end raw mode. Ctrl-C keeps
stopping the foreground job, so you can always leave a program that has hung.
A program loaded from a path never gets raw mode, and no command holds a
session through which it could ask.

## Terminal size

The shell asks its terminal service for the geometry and passes it to commands
as `COLUMNS` and `LINES` on the framebuffer console. On COM1 the kernel cannot
know the size of the host terminal, so the shell passes nothing. A program
there sends `ESC[999;999H ESC[6n`; the host terminal clamps the cursor to its
corner and answers with `ESC[rows;colsR`, which the key parser returns as a
`KeyPosition` event.

## Libraries

- `userspace/terminal` builds cursor, erase and colour sequences in a caller's
  buffer, parses keys one byte at a time, including sequences split across
  reads and the alternates host terminals send, and measures UTF-8 text in
  cells. It allocates nothing.
- `userspace/utility` gains calls that return a VFS status where `Check` and
  `Fail` end the command: `Request`, `ReadDir`, `Stat`, `Mkdir`, `Rename`,
  `Unlink` and a bounded, streaming `CopyFile`. It also gains `TerminalSize`
  and `ReadInputWithin`.
- `userspace/shell` gains `ValidName`, `JoinName`, `Parent` and `BaseName`.
- The VFS answers a rename across two filesystems with `StatusUnsupported`,
  where it answered `StatusInvalidArgument`, so `gfm` can report
  `Cross-filesystem move is not supported`.
- `tools/stackframes` accepts `LEAQ n(SP), SP` as a constant stack adjustment.
  LLVM emits it to release a frame before a conditional tail call, and the
  terminal service now contains one.

## Tests

- Host tests cover the make and break codes of every F key, the exact
  sequences, the E0 navigation keys and unknown extended codes.
- Framebuffer terminal tests cover multi-parameter CSI, CUP, CHA, the erase
  variants, all 32 foreground and background SGR codes, split and malformed
  sequences, glyph colours and the padding guards.
- Key parser and output tests cover split sequences, host-terminal alternates,
  cursor position reports, malformed input and zero allocation.
- TTY tests cover the raw protocol, the raw input buffer, geometry replies and
  the reset sequence; a VFS test covers the cross-mount rename.
- File manager tests run `gfm` against a model filesystem and a model terminal
  that fails on any write past a row or into the scrolling corner. They cover
  sorting, movement, refresh, every operation and its errors, layouts from
  80x24 to 300x200, resizing on COM1 and allocation-free frames.
- `make test-console-gui` types at the framebuffer console through QEMU's PS/2
  keyboard: an `echo`, then `gfm` with help, navigation, mkdir and F10, `ls`
  afterwards, and a second `gfm` stopped with Ctrl-C. The validation build
  lets `tty-fb` copy its output to COM1 from the first key, because the test
  reads COM1 alone.
- `make test-boot` passes its 415 checks against the COM1 session.

## Compatibility

- `GTTY` is version 3; the terminal service and the shell change together.
- `ConsoleRead`, `ConsoleInterrupt` and console waits refuse the logical
  console object; a reader needs a terminal console object.
- PID 1 receives three more boot handles: `0x19`, `0x1a` and `0x1b`.
- The command index accepts grants joined with `|`, and `GrantTerminal`.

## Remaining limitations

- `gfm` has no embedded shell or command line, mouse, viewer or editor; F3 and
  F4 say so.
- `gfm` has no archive browsing, plugins, recursive copy or delete, or
  cross-filesystem move.
- `gfm` has no permission, ownership or symlink handling, multiple selection,
  or locale collation.
- The panels show no dates and no free space: the VFS reports neither.
- The framebuffer shows ASCII, Russian Cyrillic and light box drawing; other
  characters appear as the replacement glyph.
- Colours stop at the 16 ANSI ones: no 256-colour or truecolour mode.
- An idle `gfm` on COM1 asks the host terminal for its size once a second.
- Kernel warnings and service reports still reach both screens and can land on
  a full-screen program's display until F2 repaints it.
- A program's last message before it exits disappears when raw mode clears the
  screen.
