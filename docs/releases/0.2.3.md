# GoOS 0.2.3

GoOS 0.2.3 extends the Linux compatibility layer to static glibc programs and
multithreaded workloads. It also adds a native CPU inventory and `lscpu`
command without giving userspace direct CPUID, MSR, ACPI, or APIC access.

## Highlights

- Static x86_64 glibc programs run through the existing bounded Linux
  compatibility layer alongside static musl programs (ADR 0176).
- Linux thread-form `clone`, per-thread TLS, TIDs, signal masks, and sleeping
  futex waits support real multithreaded workloads (ADR 0177, ADR 0179).
- Open Linux file descriptions survive a FAT32 service restart (ADR 0178).
- The kernel combines validated ACPI MADT processor records with decoded CPUID
  identity, topology, cache, frequency, and feature data. Only the bootstrap
  processor is online; other firmware-visible processors are present and
  offline until GoOS implements SMP (ADR 0180).
- `/system/bin/lscpu` reads fixed, versioned native records and supports
  summary, JSON, extended, parse, cache, CPU-list, and CPU-mask output.
- The kernel keeps hardware feature bits separate from features GoOS processes
  can use. It withholds extended-state and control-register-dependent features
  until it enables and preserves their required state.

## Validation

- Host tests cover CPUID decoding, topology fallbacks, cache geometry, feature
  filtering, MADT validation, inventory normalization, wire records, and
  `lscpu` formatting.
- `make test-lscpu` boots QEMU with two cores and two threads per core, checks
  all four firmware-visible CPUs, and verifies that only CPU 0 is online.
- `make test-all` and `make release-check` include the dedicated `lscpu` boot
  test.

## Limits

- GoOS still schedules only the bootstrap processor. The CPU inventory does
  not claim that present secondary processors are online.
- The kernel publishes topology only when it can map every processor
  consistently. Absent or malformed firmware data produces a conservative
  one-CPU view.
- The kernel withholds AVX-family state, FSGSBASE, PKU, and related features
  until it enables and preserves their required architectural state.
- Dynamic linking, networking, and an interactive Linux terminal remain out
  of scope.
