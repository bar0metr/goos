# GoOS 0.2.6

The native HTTPS gate passed 69 assertions, and the stream network regression
passed. Native crypto, explicit-root X.509 verification and production-bundle
loading also pass. The normal system image builds, production artifact checks
pass, and the native fetch binary reproduces byte-for-byte across separate
local toolchain roots. These results describe the earlier TLS and trust-update
tree, before the native remote administration changes below. On that tree,
full `release-check` passed, including two reproducible clean builds, storage
stress and all VM gates. The initial `test-all` stopped on an obsolete assertion
expecting three system directories; after correction to four, the release boot
gate passed 456 checks. That `test-all` VM matrix was not repeated. The extended
remote QEMU gate passed 210 checks on 2026-10-11; the exact-candidate Proxmox run
remains pending for the new tree.

GoOS 0.2.6 extends the native HTTP/1.1 `fetch` client with HTTPS using pinned
Go 1.25.5 software `crypto/tls` and `crypto/x509`, compiled with TinyGo 0.42.0.
TLS stays inside the client process over its existing GTCP1 stream. The kernel,
network driver, `netd` and `resolved` gain no TLS, X.509 or HTTP parser.

## Highlights

- HTTPS uses TLS 1.3, X25519, the standard TLS 1.3 suites and HTTP/1.1 ALPN.
- `fetch` shares HTTP request, framing and file-output code between schemes.
  Port 443 is the HTTPS default; explicit ports and numeric IPv4 URLs work
  through the same resolver/transport path.
- Existing GET, HEAD, POST, headers, `-I`, `-L`, `-o` and `-O` options apply to
  HTTPS. Followed HTTP redirects may target HTTP or HTTPS; followed HTTPS
  downgrades fail before opening the next connection. Cross-origin redirects
  strip Authorization, Proxy-Authorization, Cookie and a custom Host header.
- HTTPS retries another resolved address only after a failed TCP connect.
  Trust-store, TLS authentication and TLS protocol failures stop the request.
  HTTP 101 protocol switching fails; other informational responses precede
  the final response.
- Certificate verification uses explicit system roots, native REALTIME,
  signatures, CA/path constraints, usages and DNS/IP SAN identity. Numeric IP
  names omit SNI. Unknown critical extensions fail, and no Common Name fallback
  or insecure CLI/root-selection option bypasses verification.
- `cryptosys.Reader` supplies kernel entropy. Invalid or unavailable platform
  inputs and realtime rollback during validation fail closed. One monotonic
  35-second deadline covers the handshake; later TCP operations each have a
  35-second bound.
- Local compatibility tools pin and hash-check upstream sources, reject
  scheduler-dependent cancellation/QUIC, and disable weak certificate retention.
  They prepare temporary toolchain roots without changing installed Go, TinyGo
  or the kernel runtime. Native TLS consumers call `arena.InitPackages` after
  heap setup to run the pinned runtime's `initAll`; other native entries remain
  unchanged.
- Peer lists stop at eight certificates before allocation, DER at 32 KiB,
  DNS SAN entries at 64, and candidate chain depth at eight. The standard
  verifier retains its 100-signature-attempt budget.

## Installed trust

Production images carry 121 Mozilla-derived roots from curl's 2026-09-25
bundle as canonical PEM at `/system/security/ca-certificates.pem`, in the
read-only system namespace. The canonical file occupies 181603 bytes.
[Security provenance](../../security/README.md) records the raw source,
checksums, extraction date and MPL 2.0 license.

Normal builds use the committed artifact and check it against the pinned local
source; they download no trust material. `tools/sysimage` requires an explicit
`SYSTEM_CA_BUNDLE` input. A build may select a public fixture CA only with
`VALIDATION=1` and an explicit `VALIDATION_CA_BUNDLE`. The native client rejects
missing, empty or malformed bootstrap roots and loads no host OS roots or
unsigned application/user roots. It prefers signed valid state roots and reports
rejection before returning to the immutable system fallback.

## Validation

Host TLS tests cover authenticated transfers, identity/chain/validity/signature
failures and malformed or tampered records. Native primitive and X.509 results
appear in the [feasibility report](../development/crypto-feasibility.md).
Stock TinyGo TLS remains unusable for a generic byte stream: it can claim
handshake success without wire output. The selected software stack completed
authenticated native TLS 1.3 with AES-128-GCM/SHA-256 (cipher 4865); an earlier
native run negotiated ChaCha20-Poly1305 (4867).

The offline `make test-tls` gate passed 69 assertions using a validation tree
with a test-only root and host standard-Go TLS peers. One guest checked GET,
HEAD, redirects, HTTPS downgrade rejection, numeric IPv4 SAN and VFS output.
Bad CertificateVerify, Finished, record MACs, critical extensions, signatures,
validity, hostnames and unknown CAs failed with exit status 1. Certificate and
handshake failures produced zero HTTP requests. The peers fragment I/O to 137
bytes; no Internet endpoint participates. `tools/tlsfault` mutates one Finished
byte before the host standard library encrypts the record, without replacing
the server stack. Fixture keys are public test data and never production trust.

`make test-network NETWORK_SCENARIOS=stream` passed. The release selects the
HTTPS and trust-update gates for `test-all` and `release-check`. Before the
remote administration changes, the complete release matrix passed, including
47 trust-update assertions across three boots.

## Limits

- TLS 1.3 certificate-message buffering can reach 256 KiB before the narrower
  certificate-list and DER limits. The table records allocation and compiled
  frame measurements, not a runtime peak-stack trace.
- The client performs no CRL, OCSP, CT or AIA network requests. Mozilla/curl PEM
  omits Firefox-specific out-of-band CA name constraints.
- Session caching, persisted tickets, client certificates, TLS servers, HTTP/2,
  HTTP/3, QUIC, proxies and automatic trust updates are outside this release.
- Existing IPv4-only transport and Linux socket limitations remain. Firmware
  UTC and the pinned public-CA bundle form part of the trust boundary.
- Resolve, TCP and VFS grants remain unchanged. A narrower VFS root-read grant
  for future clients is separate work; no trust-store service is added.

[ADR 0198](../adr/0198-native-tls-and-system-trust.md) records the implementation
choice and its evidence requirements.

## Native remote administration

Native SSH offers an interactive PTY shell and non-PTY command execution:

```sh
ssh user@GOOS_ADDRESS
ssh -T user@GOOS_ADDRESS uname
ssh -T user@GOOS_ADDRESS 'net status'
ssh -T user@GOOS_ADDRESS 'log -n 5'
```

Exec uses the existing native parser and command grants, with separate stdin,
stdout and stderr streams and the command's exit status. PTY exec and background
`&` in one-shot commands fail. The interactive shell keeps its existing grammar;
`exit` closes the session, and remote `reboot`/`poweroff` drain output and close
SSH before the machine lifecycle completes.

A running `gview`, `gfm` or `edit` receives sequence-ordered resize events without
restart. Foreground startup and later events share a geometry sequence so an
older snapshot cannot replace a newer size. Background jobs receive no resize
authority. Raw exit restores cooked shell input.

Eight native images add bounded administration commands:

```text
head [-n N] FILE
tail [-n N] FILE
grep [-i] PATTERN [FILE]
wc [-l|-w|-c] [FILE]
find PATH [-name NAME]
hexdump FILE
hostname [NAME]
date [-u]
```

Head and tail default to 10 lines. Grep matches plain substrings, and find
matches exact basenames. Grep and wc read stdin without a file argument.
Hostname persists `system.hostname` through a new scoped durable mutation API;
its ASCII label has 1..63 characters and no leading/trailing hyphen. Existing
`config set` semantics remain unchanged. Date prints realtime UTC.

The log builtin adds newest matching record selection and exact structured
filters: `log -n 20`, `log --level warn`, `log --component remoted`, and combined
forms. `log -f` waits for new records without polling, with independent cursors,
ring-overwrite gap handling and Ctrl-C cancellation on local and SSH terminals.

Use `remote keys`, `remote key add "ssh-ed25519 AAAA... comment"` and
`remote key remove SHA256:...` to manage authorized keys. Valid mutations replace
the public-key file and reload policy; failures keep the previous effective set.
The command receives no host private-key authority. File replacement retains
FAT's durability limits rather than claiming a journaled cross-service commit.

Remote release acceptance requires the extended QEMU gate and one final kept
Proxmox VM on the exact candidate SHA. Use disposable client keys, pin the host
key against trusted serial `remote status`, and enable `StrictHostKeyChecking=yes`
for automated SSH. Keep the report, serial log, SHA and artifact hashes as
release evidence. On 2026-10-11, `go test ./...`, `make test-race`, additional
focused race tests, native vet and SSH compatibility host tests passed. The
extended QEMU remote gate passed 210 assertions across two persistent boots.
The network regression passed 207 checks, and console-GUI passed its console,
keyboard, filesystem, file-manager, interrupt, viewer and nested-launch checks.
The exact-candidate Proxmox remote-administration run remains the final
acceptance check; its report is retained outside source history with the SHA
and artifact hashes. The TLS results above describe the earlier release tree.

SFTP/SCP, forwarding, POSIX shells/PTYS, IPv6, dynamic linking and Linux networking
syscalls remain outside this scope. See [remote access](../development/remote-access.md)
for setup, limits and command details.

## Independent trust updates

`trust status`, `trust verify FILE META SIG`, `trust install FILE META SIG` and
`trust update` maintain signed CA data without rebuilding the OS. Production
images include the immutable Ed25519 update public key and build-configured
endpoint. HTTPS protects transport, but the signed trust package is authorized
by the immutable trust-update public key. `TRUST_UPDATE_URL` defaults to
`https://bar0metr.github.io/current` and remains overridable at build time.
The production channel publishes sequence 2026101001 with the existing 121 roots;
source date remains 2026-09-25. An explicitly empty URL disables network update.

The bootstrap artifact records trust sequence 2026092501 separately from GoOS
0.2.6. The native offline update gate passed 47 assertions on three persistent
boots: installation, new-root-only HTTPS, rollback and bad signature refusal,
reboot persistence, selector recovery and corrupt-package bootstrap fallback.
The production signing seed lives outside the repository and images; validation
uses a distinct public test key. See [maintenance instructions](../../security/README.md).
