# GoOS 0.2.6

The native HTTPS gate passed 69 assertions, and the stream network regression
passed. Native crypto, explicit-root X.509 verification and production-bundle
loading also pass. The normal system image builds, production artifact checks
pass, and the native fetch binary reproduces byte-for-byte across separate
local toolchain roots. Full `test-all` and `release-check` have not run.

GoOS 0.2.6 extends the native HTTP/1.1 `fetch` client with HTTPS using pinned
Go 1.25.5 software `crypto/tls` and `crypto/x509`, compiled with TinyGo 0.42.0.
TLS stays inside the client process over its existing GTCP1 stream. The kernel,
network driver, `netd` and `resolved` gain no TLS, X.509 or HTTP parser.

## Highlights

- HTTPS uses TLS 1.3, X25519, the standard TLS 1.3 suites and HTTP/1.1 ALPN.
- `fetch` shares HTTP request, framing and file-output code between schemes.
  Port 443 is the HTTPS default; explicit ports and numeric IPv4 URLs work
  through the same resolver/transport path.
- Existing GET, HEAD, POST, headers, `-I`, `-L`, `-o` and `-O` options apply to
  HTTPS. Followed HTTP redirects may target HTTP or HTTPS; followed HTTPS
  downgrades fail before opening the next connection. Cross-origin redirects
  strip Authorization, Proxy-Authorization, Cookie and a custom Host header.
- Certificate verification uses explicit system roots, native REALTIME,
  signatures, CA/path constraints, usages and DNS/IP SAN identity. Numeric IP
  names omit SNI. Unknown critical extensions fail, and no Common Name fallback
  or insecure CLI/root-selection option bypasses verification.
- `cryptosys.Reader` supplies kernel entropy. Invalid or unavailable platform
  inputs and realtime rollback during validation fail closed. One monotonic
  35-second deadline covers the handshake; later TCP operations each have a
  35-second bound.
- Local compatibility tools pin and hash-check upstream sources, reject
  scheduler-dependent cancellation/QUIC, and disable weak certificate retention.
  They prepare temporary toolchain roots without changing installed Go, TinyGo
  or the kernel runtime. Native TLS consumers call `arena.InitPackages` after
  heap setup to run the pinned runtime's `initAll`; other native entries remain
  unchanged.
- Peer lists stop at eight certificates before allocation, DER at 32 KiB,
  DNS SAN entries at 64, and candidate chain depth at eight. The standard
  verifier retains its 100-signature-attempt budget.

## Installed trust

Production images carry 121 Mozilla-derived roots from curl's 2026-09-25
bundle as canonical PEM at `/system/security/ca-certificates.pem`, in the
read-only system namespace. The canonical file occupies 181603 bytes.
[Security provenance](../../security/README.md) records the raw source,
checksums, extraction date and MPL 2.0 license.

Normal builds use the committed artifact and check it against the pinned local
source; they download no trust material. `tools/sysimage` requires an explicit
`SYSTEM_CA_BUNDLE` input. A build may select a public fixture CA only with
`VALIDATION=1` and an explicit `VALIDATION_CA_BUNDLE`. The native client rejects
missing, empty or malformed roots and loads no host OS roots or mutable
application/user/state fallback.

## Validation

Host TLS tests cover authenticated transfers, identity/chain/validity/signature
failures and malformed or tampered records. Native primitive and X.509 results
appear in the [feasibility report](../development/crypto-feasibility.md).
Stock TinyGo TLS remains unusable for a generic byte stream: it can claim
handshake success without wire output. The selected software stack completed
authenticated native TLS 1.3 with AES-128-GCM/SHA-256 (cipher 4865); an earlier
native run negotiated ChaCha20-Poly1305 (4867).

The offline `make test-tls` gate passed 69 assertions using a validation tree
with a test-only root and host standard-Go TLS peers. One guest checked GET,
HEAD, redirects, HTTPS downgrade rejection, numeric IPv4 SAN and VFS output.
Bad CertificateVerify, Finished, record MACs, critical extensions, signatures,
validity, hostnames and unknown CAs failed with exit status 1. Certificate and
handshake failures produced zero HTTP requests. The peers fragment I/O to 137
bytes; no Internet endpoint participates. `tools/tlsfault` mutates one Finished
byte before the host standard library encrypts the record, without replacing
the server stack. Fixture keys are public test data and never production trust.

`make test-network NETWORK_SCENARIOS=stream` passed. The release selects the
HTTPS gate for `test-all` and `release-check`, but neither complete gate has run.

## Limits

- TLS 1.3 certificate-message buffering can reach 256 KiB before the narrower
  certificate-list and DER limits. The table records allocation and compiled
  frame measurements, not a runtime peak-stack trace.
- The client performs no CRL, OCSP, CT or AIA network requests. Mozilla/curl PEM
  omits Firefox-specific out-of-band CA name constraints.
- Session caching, persisted tickets, client certificates, TLS servers, HTTP/2,
  HTTP/3, QUIC, proxies and automatic trust updates are outside this release.
- Existing IPv4-only transport and Linux socket limitations remain. Firmware
  UTC and the pinned public-CA bundle form part of the trust boundary.
- Resolve, TCP and VFS grants remain unchanged. A narrower VFS root-read grant
  for future clients is separate work; no trust-store service is added.

[ADR 0198](../adr/0198-native-tls-and-system-trust.md) records the implementation
choice and its evidence requirements.
