# GoOS 0.1.1

An architectural cleanup release. It adds no user-visible features. It removes
shortcuts 0.1.0 took, before Linux compatibility — the next milestone — builds
on them.

## What changed

### Launch by image extent, not by path (ADR 0093)

The kernel no longer resolves application paths. PID 1 maps the read-only
system image and resolves `/system/...` there; a launch request names an extent
of the image (offset and length) and the image handle it may execute from.
The kernel requires Execute on that handle, checks the extent against the
image, and validates the bytes as a native image. The only name the kernel
still knows is the bootstrap `system/init`. The VFS keeps a Read-only copy of
the image capability and cannot launch anything.

### FAT32 is a separate service (ADR 0096)

The FAT32 parser and filesystem ran inside the VFS process, which also held
the block endpoint. It is now `/system/fat32`, a process holding only a channel
to the VFS and a block client endpoint. The VFS reaches it through a typed,
versioned protocol (`GFSPRT01`) with bounded messages and a deadline on every
exchange. A dead or stalled FAT32 service is an I/O error on `/persist`,
`/home` and `/state` only. The service restarts on failure, and the VFS keeps
its mounts and open files across the restart; the validation boot test kills it
under a running system and reads the volume again through the new instance.

### No identity-authorized console output (ADR 0094)

`DebugWrite`, a console write authorized by comparing the caller's address
space with PID 1's, is retired in every build; its operation number answers
`Unsupported`. PID 1 prints through its console capability like every other
process.

### Userspace `unsafe` confined to `userspace/runtime` (ADR 0095)

Every service had its own native-call stubs, allocator hooks, and pointer
conversions. They are now two packages: `userspace/runtime/sys`, typed
wrappers for every native call and the kernel-mapped windows, and
`userspace/runtime/arena`, the allocator. `make lint` refuses `unsafe`,
`//go:linkname`, and `//go:extern` anywhere else in userspace, and checks
itself before it runs.

### Smaller source files

`kernel/main.go` (2,297 lines) is split into launch, lifecycle, channel,
stream, wait, device and task files; PID 1's main (1,616 lines) into service
declarations, launch, restart supervision, lifecycle, exec, applications,
shutdown, probes, filesystem and image files; the shell's main (1,619 lines)
into terminal, execution, builtins, configuration, pipeline, job and session
files. Behavior is unchanged.

### Documentation and release validation

The documentation is checked against the implementation: stderr redirection
(`2>`, `2>>`), the native application environment, the launch path, the
storage stack, and the console policy are described as they are. `make docs`
also checks every relative link and every ADR's structure. `make release-check`
is the release gate: a reproducible clean build, lint, documentation, unit,
integration and security tests, the ISO, the validation boot test, a stress
run, and release checks — the version and its notes, no validation code in the
normal images, and no generated file outside `build/`.

## Compatibility

The native environment of 0.1.0 is preserved: boot, the scheduler and
event-driven waits, processes and tasks, handles and capabilities, typed IPC,
shared memory, the terminal, VFS, RAMFS, persistent FAT32 data (volumes written
by 0.1.0 mount unchanged), the block service and driver, configuration and
logging, the shell with pipelines, redirection and background jobs, process
wait and kill, the utilities, and shutdown.

Wire versions that changed, all internal to the system image: lifecycle launch
requests (version 7, image extents), the VFS control protocol (version 4, adds
`SetFilesystem`), the block control protocol (version 2, adds
`SetFilesystem`). New: the filesystem-service protocol, version 1. Native
operation 2 is retired. The native ABI is still not declared stable.

## Performance

Measured against 0.1.0 at 100 Hz under QEMU TCG on the same host, both disk
images on the same volume (medians of 10): commands off the persistent volume,
IPC ping-pong, streams, and RAMFS are unchanged within noise; a missing command
is answered 26% faster, since PID 1 no longer asks the kernel. Persistent
operations pay for the separate FAT32 process: `cat /persist/...` +6%,
`echo y > /persist/...` +7%, a 16 KiB uncached read +13% (ADR 0096). The
timer configuration is unchanged.

## Known limitations

This release removes only the four architectural shortcuts described above.
Every other limitation of 0.1.0 still holds:

- One CPU, QEMU q35 only. Real hardware is not a target yet.
- No Linux ABI compatibility of any kind. It is the next milestone.
- No IOMMU: a compromised storage driver's DMA is not confined to its buffers.
- No ASLR: the kernel and user address layouts are fixed.
- No verified or Secure Boot chain.
- CPU time is accounted per process but never limited.
- PID 1 holds every initial capability and remains a single point of
  authority.
- Services that start before the terminal, and the kernel's warning echo,
  still write the console directly, so their output can land in a line being
  typed.
- A kernel stack overflow is reported, but the kernel cannot recover from it.

In addition:

- The VFS does not restart: every session and open file lives in it.
- A write in flight when the FAT32 service dies may be partly applied; FAT32
  has no journal.
- File data between the VFS and FAT32 moves through IPC payloads, at most 216
  bytes per write and 224 per read; the shared-memory page cache is future
  work.
- Executables can only come from the system image; the launch interface has
  room for a memory-object source, which persistent executables will need.
