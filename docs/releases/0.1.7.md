# GoOS 0.1.7

GoOS 0.1.7 makes the native environment usable end to end. You can list
mounts and free space, browse files in `gfm` with their times and sizes, view
any file with `gview`, edit and save one with `edit`, and return to `gfm`
after each. Saving never truncates the original, and `gfm` starts the viewer
and the editor through PID 1 with no authority beyond what their own manifests
declare.

## Implemented

### Native file metadata

- `stat` and directory listings carry fixed-width creation/modification time,
  native attributes and VFS mount identity (ADR 0126).
- FAT32 translates validated directory-entry metadata at the filesystem
  boundary. RAMFS records native realtime timestamps. The immutable system
  image reports read-only state without fabricating timestamps.
- `GFSPRT01` and `GVF1` are version 10. Their decoders validate availability
  flags, attribute bits, nanosecond ranges and reserved fields.
- `stat` prints modification time, attributes and mount ID while preserving
  its existing size summary.

### Filesystem capacity and mounts

- Native filesystem information carries a stable type, checked 64-bit total,
  free and available bytes, read-only state and an optional bounded label (ADR
  0127).
- Queries select a mount by path or generation-safe mount ID. VFS exposes its
  fixed mount table through bounded cursor enumeration without leaking backend
  handles or capabilities.
- RAMFS reports its configured page quota, the system image reports its archive
  length with no reusable space, and FAT32 derives capacity from validated
  geometry and a live FAT free-cluster count.
- Protocol decoders reject impossible capacity relations, unknown flags and
  types, nonzero reserved bytes, overlong labels and incomplete success replies.

### Native filesystem commands

- `df` enumerates mounts and reports deterministic binary size, used and free
  columns without floating point. Unavailable capacity is printed as `-`.
- `mount` is read-only and lists mount path, filesystem type and `ro`/`rw`
  state. Neither command receives device or filesystem-service authority.
- Host tests cover formatting, overflow boundaries and unavailable capacity.
  Existing COM1 and framebuffer QEMU scenarios execute both commands.

### Reusable terminal-cell TUI

- `userspace/tui` adds checked rectangles, caller-owned screens, semantic
  16-colour roles, clipped text and borders, status bars, dialogs, list
  viewports and scrollable text viewports (ADR 0128).
- Dirty-row flushing uses absolute terminal cursor movement, allocates nothing
  for changed steady-state frames and never writes the scrolling bottom-right
  cell.
- Host model-terminal tests cover 80x24 rendering, large-dimension overflow,
  clipping, UTF-8 text, selection/cursor overlays and zero allocations.
- `gfm` remains on its proven application-specific renderer; no speculative
  migration was made before a second application consumes the shared layer.

### Bounded text viewer

- `/system/bin/gview` opens one regular file through VFS and renders through
  `userspace/tui`; Up/Down, PageUp/PageDown, Home/End and horizontal scrolling
  are supported, while Escape and F10 return to the shell.
- A fixed 4 KiB model window over the existing 64 KiB VFS bulk transport keeps
  memory independent of file size. End and reverse navigation scan through that
  bounded cache instead of building a whole-file line index.
- Status shows the path, byte size, first visible offset and percentage. Long
  paths and lines are clipped without corrupting terminal geometry.
- NUL/control-heavy input is reported as binary. ESC, CSI and other file control
  bytes are converted to visible data before rendering and cannot inject
  terminal commands.
- Host tests cover a synthetic 1 GiB file, long lines, navigation, invalid
  UTF-8, binary/control data, read failures and allocation-free frames. The
  canonical COM1 and framebuffer QEMU scenarios open, navigate and exit the
  viewer.

### Safe file replacement

- `GVF1` and `GFSPRT01` are version 11 and add `Replace`: a regular file takes
  the place of an existing one on the same filesystem, or is renamed when the
  target is missing (ADR 0129). Rename still refuses an existing target.
- The VFS refuses to replace a directory, a mount root or a file any session
  holds open.
- RAMFS replaces inside one request. FAT32 flushes the new file, erases its
  entry, rewrites the target's short entry in place and frees the old chain,
  with a device flush after each step. A power loss leaves the old or the new
  file whole and at worst lost clusters, which `fsck-fat` repairs. GoOS does
  not claim journal-level atomicity.
- `userspace/safesave` writes `.<name>.~save` beside the target, closes it and
  replaces. A failure at any step leaves the original untouched and removes
  the temporary file. Host tests fail every step in turn and cut a FAT32
  replacement at each device write.

### Native text editor

- `/system/bin/edit FILE` opens a UTF-8 text file or starts a new one. It
  supports arrows, Home/End, PageUp/PageDown, UTF-8 insertion, Enter,
  Backspace and Delete. F2 saves, F3 saves under another name, and F10 quits,
  asking before it drops unsaved changes (ADR 0131).
- The document is a gap buffer in a fixed 1 MiB array. Larger files and files
  containing NUL are refused with a pointer to `gview`. No keystroke copies the
  whole document.
- Every save goes through `utility.SaveFile`. A read-only mount, a full volume,
  a dead service or a file open elsewhere is a message; the buffer stays
  modified and the file keeps its old contents.
- File control bytes show as `?`, so file contents cannot drive the terminal,
  and a save writes the document's bytes unchanged.

### Application launch

- A command whose manifest declares the new `GrantLaunch`, running as the only
  stage of a foreground job, gets a launch channel to PID 1 (ADR 0130).
- Over it the command can run one `/system/bin` command that declares
  `GrantTerminal` and wait for its exit code. PID 1 checks the request against
  the command index. The child gets its own manifest's grants and a new VFS
  session, and never `GrantLaunch`. The caller passes no handles; the child
  reads the caller's input from a copy PID 1 kept.
- The caller stays the shell's foreground job and reads nothing while the child
  runs, so one program takes the keys at a time and raw mode keeps its ADR 0124
  scope. A job that ends while its child runs has the child stopped first.

### File manager

- F3 views and F4 edits the selected file; Enter on a file views it. After the
  program exits, `gfm` rereads both panels, keeps the selected entry and
  repaints the whole screen. A launch failure or a nonzero exit is a
  status-line message.
- Panels wide enough show a `Modified` column in UTC; at 80 columns the
  information line carries the selected entry's time.
- Each panel's bottom frame shows its filesystem's free and total space, or
  `ro` for a read-only one. `gfm` asks when it lists a directory and never on
  cursor movement.
- A rename within the active panel keeps the renamed entry selected.

### Validation

- The COM1 boot test and the framebuffer console test both run `gfm`, view a
  file, edit and save it, leave both programs and read the saved file back.
- `make test-all` passes.

### Hardening

- `ls`, `mount`, `df`, `pwd` and every command's error message print names
  through `terminal.Printable`: C0 controls, DEL, C1 controls and bytes that
  start no UTF-8 character appear as `?`. `gfm`, `gview` and `edit` apply the
  same rule on screen. A file name, a file's contents or a volume label cannot
  reach the terminal as a command.
- The COM1 boot test restarts the terminal service and then runs `gview`,
  restarts the VFS and then runs `gfm` and the viewer it starts, and stops
  `gfm` with Ctrl-C while its editor runs; the shell must read lines each time
  and `ps` must list neither program.
- A command that loses its VFS session to a VFS restart reports
  `storage service unavailable` for each operation and keeps running;
  programs started after the restart get new sessions.
- The build now refuses an initramfs over `boot.MaxInitramfs`, which it did
  not before, and the bound is 6 MiB (ADR 0087 addendum).

### Bounds

| What | Bound |
| --- | --- |
| mounts enumerated | 8, the VFS mount table |
| metadata and capacity replies | one fixed-size IPC message; labels up to the volume-name limit |
| `gfm` listing | 1024 entries and 64 KiB of names per panel |
| `gfm` capacity queries | one per directory listing, none per key |
| TUI screens | caller-owned, up to 256x128 cells |
| `gview` memory | a 4 KiB model window and the 64 KiB bulk buffer, whatever the file size |
| `edit` document | 1 MiB gap buffer; larger files are refused |
| launch request | one exec slot, copied before it is decoded |
| launched children | one per caller, one level deep |
| save | one temporary file beside the target |

Byte counts, cluster arithmetic and timestamps are checked where they are
decoded (ADR 0126, ADR 0127); the TUI rejects screen dimensions whose product
overflows (ADR 0128).

## Compatibility

- `GVF1` and `GFSPRT01` are version 11. The VFS, the filesystem services and
  every client change together.
- `commands.GrantLaunch` is a new grant; the command index encodes it as 8.
- `utility.DirVisitor` and `filemanager.Visitor` receive a modification time.
- `boot.MaxInitramfs` is 6 MiB and the kernel's panic message says so.

## Remaining limitations

- A launched child cannot launch another; only `/system/bin` commands that
  declare `GrantTerminal` can be launched, and only one at a time.
- `edit` has no undo, search, selection or line wrap, and refuses files over
  1 MiB.
- `gview` has no hex mode; binary files get a message.
- A command started before a VFS restart keeps a dead session until it exits.
- Kernel warnings and service reports can still land on a full-screen
  program's display until it repaints.
- FAT32 replacement is ordered and flushed, not journaled: a power loss can
  leave lost clusters for `fsck-fat`.
- No recursive copy or delete, cross-filesystem move, symlinks, permissions or
  owners, mouse, 256-colour output or Linux binaries. Linux ABI compatibility
  is the next milestone.
