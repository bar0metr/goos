# GoOS 0.1.7

GoOS 0.1.7 turns the native environment into an end-to-end usable workspace.
It adds filesystem metadata and capacity reporting, `df` and `mount`, a reusable
terminal-cell TUI layer, the bounded `gview` text viewer, the native `edit`
editor, safe file replacement, and capability-bounded application launch.

`gfm` can now show modification times and filesystem capacity, open selected
files in `gview`, launch `edit`, and return to the same selection after the
child application exits. The viewer is designed for arbitrarily large text
files without loading the whole file into memory, while the editor deliberately
uses a bounded 1 MiB document model.

Saving does not destructively truncate the original before a replacement is
ready. Application launch remains mediated by PID 1 and does not let the caller
grant capabilities to the child.

## Highlights

- Native file creation/modification metadata and mount identity.
- Filesystem type, capacity, free-space and read-only queries.
- New `df` and read-only `mount` commands.
- Reusable `userspace/tui` terminal-cell primitives.
- `gview`: bounded-memory text viewer.
- `edit`: native text editor with safe save/save-as.
- Capability-bounded nested application launch through PID 1.
- `gfm` F3/F4 integration with viewer/editor.
- Stronger terminal-injection hardening and restart coverage.
- Final VFS/filesystem protocol version for this release: **11**.

## Implemented

### Native file metadata

- `stat` and directory listings now carry fixed-width creation/modification
  timestamps, native attributes and VFS mount identity (ADR 0126).
- FAT32 translates validated directory-entry metadata at the filesystem
  boundary.
- RAMFS records native realtime timestamps.
- The immutable system image reports read-only state without fabricating
  timestamps.
- Metadata decoders validate availability flags, attribute bits, nanosecond
  ranges and reserved fields.
- `stat` prints modification time, attributes and mount ID while preserving its
  existing size summary.

### Filesystem capacity and mounts

- Native filesystem information carries:
  - stable filesystem type;
  - checked 64-bit total, free and available byte counts;
  - read-only state;
  - optional bounded volume label;
  - generation-safe mount identity.
- Queries can select a mount by path or mount ID.
- VFS exposes its fixed mount table through bounded cursor enumeration without
  leaking backend handles or capabilities (ADR 0127).
- RAMFS reports its configured page quota.
- The immutable system image reports its archive length with no reusable space.
- FAT32 derives capacity from validated geometry and a live FAT free-cluster
  count.
- Protocol decoders reject impossible capacity relations, unknown flags/types,
  nonzero reserved bytes, overlong labels and incomplete successful replies.

### Native filesystem commands

- `df` enumerates mounts and reports deterministic binary size, used and free
  columns without floating point.
- Unavailable capacity is shown as `-`.
- `mount` is informational/read-only and lists mount path, filesystem type and
  `ro`/`rw` state.
- Neither command receives block-device or filesystem-service authority.
- Host tests cover formatting, overflow boundaries and unavailable capacity.
- Existing COM1 and framebuffer QEMU scenarios execute both commands.

### Reusable terminal-cell TUI

- `userspace/tui` adds:
  - checked rectangles;
  - caller-owned screens;
  - semantic 16-colour roles;
  - clipped text and borders;
  - status bars;
  - dialogs;
  - list viewports;
  - scrollable text viewports.
- Dirty-row flushing uses absolute terminal cursor movement.
- Changed steady-state frames allocate no memory.
- The renderer never writes the terminal's scrolling bottom-right cell.
- Model-terminal tests cover 80x24 rendering, large-dimension overflow,
  clipping, UTF-8, selection/cursor overlays and zero-allocation rendering
  (ADR 0128).
- `gfm` keeps its existing application-specific renderer in 0.1.7; the shared
  layer is consumed by the new applications instead of forcing a speculative
  rewrite of proven code.

### Bounded text viewer

`/system/bin/gview` is a native full-screen text viewer.

- Opens one regular file through VFS and renders through `userspace/tui`.
- Supports:
  - Up/Down;
  - PageUp/PageDown;
  - Home/End;
  - horizontal scrolling;
  - Escape/F10 to exit.
- Uses a fixed 4 KiB model window over the existing 64 KiB VFS bulk transport,
  so memory use is independent of file size.
- Reverse navigation and End scan through the bounded cache instead of building
  a whole-file line index.
- Status shows path, byte size, first visible offset and percentage.
- Long paths and lines are clipped without corrupting terminal geometry.
- NUL/control-heavy input is treated as binary rather than rendered as terminal
  data.
- ESC, CSI and other control bytes are converted to visible/safe data before
  rendering and cannot inject terminal commands.
- Host tests include a synthetic 1 GiB file, long lines, invalid UTF-8,
  binary/control data, navigation, read failures and allocation-free frames.
- Canonical COM1 and framebuffer QEMU scenarios open, navigate and exit the
  viewer.

`gview` is a text viewer in 0.1.7; it does not provide a hex/binary viewer.

### Safe file replacement

VFS/filesystem protocol version 11 adds `Replace` (ADR 0129).

- A regular file can replace an existing regular file on the same filesystem,
  or be renamed to the target if the target does not yet exist.
- Ordinary `Rename` still refuses an existing target.
- VFS refuses replacement of:
  - directories;
  - mount roots;
  - files held open by any session.
- RAMFS performs replacement inside one request.
- FAT32 uses an ordered, flushed replacement sequence and does **not** claim
  journal-level atomicity.
- `userspace/safesave` writes a temporary `.<name>.~save` file beside the
  target, closes it, then performs replacement.
- Failures before replacement leave the original file untouched; temporary
  cleanup is attempted before returning the error.
- Host tests inject failure at every safe-save step and cut FAT32 replacement
  at each device-write boundary.

Under the tested device-write-boundary failure model, recovery leaves either
the old or new file reachable; interrupted FAT32 replacement may leave lost
clusters that `fsck-fat` can repair. This release does **not** claim protection
against arbitrary torn-sector writes, devices that violate flush semantics, or
journal-level crash atomicity.

### Native text editor

`/system/bin/edit FILE` is the first native GoOS text editor (ADR 0131).

- Opens an existing UTF-8 text file or starts a new one.
- Supports:
  - arrows;
  - Home/End;
  - PageUp/PageDown;
  - UTF-8 insertion;
  - Enter;
  - Backspace;
  - Delete.
- F2 saves.
- F3 performs Save As.
- F10 quits and asks before discarding unsaved changes.
- The document is stored in a fixed 1 MiB gap buffer.
- Files larger than 1 MiB and files containing NUL are refused with guidance to
  use `gview`.
- Ordinary editing does not copy the whole document for each keystroke.
- Every save goes through `utility.SaveFile`.
- Read-only filesystems, full volumes, dead storage services and files held open
  elsewhere are reported in-app; the editor remains modified and the old file
  contents remain intact.
- File control bytes display as `?`, while successful saves preserve the
  document bytes themselves.

### Capability-bounded application launch

0.1.7 adds a deliberately narrow native application-launch path through PID 1
(ADR 0130).

- A command whose immutable manifest declares `GrantLaunch`, running as the
  only stage of a foreground job, receives a launch channel to PID 1.
- The caller can launch one `/system/bin` command that itself declares
  `GrantTerminal` and wait for its exit status.
- PID 1 validates the request against the system command index.
- The child receives its own manifest-defined grants and a fresh VFS session.
- The child never inherits `GrantLaunch`.
- The caller cannot pass arbitrary handles or manufacture capabilities for the
  child.
- The caller remains the shell's foreground job and does not consume input
  while the child is active, so exactly one full-screen application receives
  keys at a time.
- Raw terminal mode remains scoped to the original foreground job.
- If the parent job ends while its child is active, PID 1 stops the child
  first.

This is intentionally **not** a general-purpose `fork`/`exec` API and does not
attempt to copy POSIX process semantics.

### File manager integration

`gfm` now uses the 0.1.7 metadata and launch facilities.

- F3 opens the selected regular file in `gview`.
- F4 opens the selected regular file in `edit`.
- Enter on a regular file opens it in `gview`.
- After a child application exits, `gfm`:
  - rereads both panels;
  - preserves the selected entry where possible;
  - repaints the full screen.
- Launch failures and nonzero child exits are shown on the status line.
- Wider panels show a `Modified` column in UTC.
- At 80 columns, the selected entry's timestamp moves to the information line.
- Each panel footer shows filesystem free/total space, or `ro` for a read-only
  filesystem.
- Capacity is queried when the directory is listed, not on every cursor move.
- Rename within the active panel keeps the renamed entry selected.

### Hardening

- `ls`, `mount`, `df`, `pwd` and command error messages pass untrusted names
  through `terminal.Printable`.
- `gfm`, `gview` and `edit` apply the same safety rule on screen.
- C0 controls, DEL, C1 controls and bytes that cannot start valid UTF-8 display
  as `?`.
- Filenames, file contents and volume labels therefore cannot directly inject
  terminal control sequences.
- The COM1 boot test covers:
  - terminal-service restart followed by `gview`;
  - VFS restart followed by `gfm`;
  - launching `gview` from `gfm` after VFS recovery;
  - stopping `gfm` with Ctrl-C while its editor child runs;
  - returning to a usable shell;
  - verifying neither child remains in `ps`.
- A command that loses its existing VFS session after a VFS restart reports
  `storage service unavailable` instead of silently switching authority.
  Programs started after the restart receive fresh sessions.
- The build now rejects initramfs images larger than `boot.MaxInitramfs`;
  the current limit is 6 MiB (ADR 0087 addendum).

## Validation

- The COM1 boot test and framebuffer console test both run `gfm`.
- Both scenarios open a file in `gview`.
- Both launch `edit`, modify and save the file, exit back through `gfm`, and
  read the saved file back.
- Host-side tests cover the new protocol, TUI, viewer, editor, safe-save and
  launch behavior.
- `make test-all` passes for the release candidate.

## Bounds

| What | Bound |
| --- | --- |
| mounts enumerated | 8, the fixed VFS mount table |
| metadata/capacity replies | one fixed-size IPC message; label bounded by the volume-name limit |
| `gfm` listing | 1024 entries and 64 KiB of names per panel |
| `gfm` capacity queries | one per directory listing, none per key |
| TUI screens | caller-owned, up to 256x128 cells |
| `gview` model memory | 4 KiB window plus the existing 64 KiB bulk buffer, independent of file size |
| `edit` document | fixed 1 MiB gap buffer |
| launch request | one exec slot, copied before decoding |
| launched children | one per caller, one level deep |
| safe save | one temporary file beside the target |

Byte counts, cluster arithmetic and timestamps are checked at decode/conversion
boundaries (ADR 0126, ADR 0127). TUI geometry rejects screen dimensions whose
product overflows (ADR 0128).

## Compatibility

- Final `GVF1` and `GFSPRT01` protocol version for 0.1.7 is **11**.
- VFS, filesystem services and all in-tree clients move together.
- `commands.GrantLaunch` is new and is encoded as grant value `8`.
- `utility.DirVisitor` and `filemanager.Visitor` now receive modification time.
- `boot.MaxInitramfs` is 6 MiB and the kernel panic message reports that bound.

## Remaining limitations

- A launched child cannot launch another child.
- Only `/system/bin` commands that declare `GrantTerminal` can be launched
  through the new application-launch path.
- Only one launched child may exist per caller, one level deep.
- `edit` has no undo, search, selection or line wrapping and refuses documents
  over 1 MiB.
- `gview` has no hex mode; binary files are reported rather than displayed.
- A command started before a VFS restart keeps its dead session until it exits.
- Kernel warnings and service reports may still land on a full-screen
  application's display until it repaints.
- FAT32 replacement is ordered and flushed, not journaled. Under interruption
  it may leave lost clusters for `fsck-fat`.
- No recursive copy/delete, cross-filesystem move, symlink management,
  permissions/owners, mouse, 256-colour output or Linux binary compatibility.

Linux ABI compatibility is the next major milestone.
