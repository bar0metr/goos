# GoOS 0.1.7

Status: in development.

## Implemented

### Native file metadata

- `stat` and directory listings carry fixed-width creation/modification time,
  native attributes and VFS mount identity (ADR 0126).
- FAT32 translates validated directory-entry metadata at the filesystem
  boundary. RAMFS records native realtime timestamps. The immutable system
  image reports read-only state without fabricating timestamps.
- `GFSPRT01` and `GVF1` are version 10. Their decoders validate availability
  flags, attribute bits, nanosecond ranges and reserved fields.
- `stat` prints modification time, attributes and mount ID while preserving
  its existing size summary.

### Filesystem capacity and mounts

- Native filesystem information carries a stable type, checked 64-bit total,
  free and available bytes, read-only state and an optional bounded label (ADR
  0127).
- Queries select a mount by path or generation-safe mount ID. VFS exposes its
  fixed mount table through bounded cursor enumeration without leaking backend
  handles or capabilities.
- RAMFS reports its configured page quota, the system image reports its archive
  length with no reusable space, and FAT32 derives capacity from validated
  geometry and a live FAT free-cluster count.
- Protocol decoders reject impossible capacity relations, unknown flags and
  types, nonzero reserved bytes, overlong labels and incomplete success replies.

### Native filesystem commands

- `df` enumerates mounts and reports deterministic binary size, used and free
  columns without floating point. Unavailable capacity is printed as `-`.
- `mount` is read-only and lists mount path, filesystem type and `ro`/`rw`
  state. Neither command receives device or filesystem-service authority.
- Host tests cover formatting, overflow boundaries and unavailable capacity.
  Existing COM1 and framebuffer QEMU scenarios execute both commands.

### Reusable terminal-cell TUI

- `userspace/tui` adds checked rectangles, caller-owned screens, semantic
  16-colour roles, clipped text and borders, status bars, dialogs, list
  viewports and scrollable text viewports (ADR 0128).
- Dirty-row flushing uses absolute terminal cursor movement, allocates nothing
  for changed steady-state frames and never writes the scrolling bottom-right
  cell.
- Host model-terminal tests cover 80x24 rendering, large-dimension overflow,
  clipping, UTF-8 text, selection/cursor overlays and zero allocations.
- `gfm` remains on its proven application-specific renderer; no speculative
  migration was made before a second application consumes the shared layer.

### Bounded text viewer

- `/system/bin/gview` opens one regular file through VFS and renders through
  `userspace/tui`; Up/Down, PageUp/PageDown, Home/End and horizontal scrolling
  are supported, while Escape and F10 return to the shell.
- A fixed 4 KiB model window over the existing 64 KiB VFS bulk transport keeps
  memory independent of file size. End and reverse navigation scan through that
  bounded cache instead of building a whole-file line index.
- Status shows the path, byte size, first visible offset and percentage. Long
  paths and lines are clipped without corrupting terminal geometry.
- NUL/control-heavy input is reported as binary. ESC, CSI and other file control
  bytes are converted to visible data before rendering and cannot inject
  terminal commands.
- Host tests cover a synthetic 1 GiB file, long lines, navigation, invalid
  UTF-8, binary/control data, read failures and allocation-free frames. The
  canonical COM1 and framebuffer QEMU scenarios open, navigate and exit the
  viewer.

## Remaining 0.1.7 work

Safe replacement, the editor, controlled nested launch, `gfm` integration,
hardening and release-wide QEMU coverage are not yet implemented.
