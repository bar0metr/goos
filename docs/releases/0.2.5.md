# GoOS 0.2.5

GoOS 0.2.5 adds native IPv4 networking from the device driver to an HTTP
client. A capability-scoped userspace virtio-net driver moves Ethernet frames,
`netd` owns IPv4 networking, `resolved` provides cached DNS resolution, and
ordinary native programs can use generic UDP and TCP sessions without putting
sockets or protocol parsers in the kernel.

The release includes DHCP, ARP, ICMP echo, loopback, configurable IPv4, DNS
with TCP fallback, direct DNS diagnostics, generic UDP/TCP clients and
servers, and a native HTTP/1.1 `fetch` client. The network gate tests these
paths offline.

## Highlights

- A userspace legacy virtio-net driver owns only the PCI ports, interrupt line
  and DMA window required for one network device.
- `netd` runs Ethernet, ARP, IPv4, ICMP echo, DHCP, UDP and TCP entirely in
  userspace; the kernel contains no IP, UDP, TCP, DNS or HTTP parser.
- Network boot is optional: a machine without a usable NIC still boots its
  installed system, storage and shell normally.
- DHCP configures an IPv4 address, prefix, router and DNS servers, including
  lease renewal, expiry and RFC 5227 address-conflict detection.
- Static IPv4 configuration and bounded runtime network tuning are available
  through the configuration service and `net reload`.
- The `lo` interface provides `127.0.0.0/8` without a network device, including
  ICMP, UDP and TCP traffic through the same stack.
- The native `ping` command accepts IPv4 addresses and host names.
- `resolved` is a supervised userspace stub resolver with hosts-file lookup,
  `localhost`, CNAME handling, EDNS(0), bounded positive/negative/failure
  caches, configurable upstream servers and per-query deadlines.
- DNS responses truncated over UDP are retried against the same server over
  TCP, with the same logical query deadline.
- Generic IPv4 UDP is exposed through capability-scoped GUDP1 sessions.
  Programs can open, bind, connect, send, receive and use loopback without
  owning the network device.
- Generic IPv4 TCP is exposed through GTCP1 sessions with active and passive
  open, listeners, accept, retransmission, flow and congestion control,
  out-of-order receive handling, half-close, reset handling and TIME_WAIT.
- TCP endpoint IDs are generation-safe. Recycled TIME_WAIT slots retain their
  old four-tuples in bounded tombstones, so delayed segments cannot match a
  new connection.
- The `udp` and `tcp` commands exercise the generic transports directly.
- `dnsq` is a direct DNS diagnostic command independent of `resolved`. It
  supports UDP, forced TCP, automatic truncated-answer fallback, EDNS(0), and
  A, AAAA, CNAME, NS, MX, TXT, SOA and PTR records.
- DNS wire parsing and DNS-over-TCP framing are shared by the resolver and
  `dnsq` through bounded `dnswire` and `dnstcp` packages.
- The native `fetch` command provides an HTTP/1.1 application on top of the
  resolver, GTCP1 and VFS. It supports GET, HEAD and POST, custom headers,
  redirects, Content-Length, chunked and EOF-delimited bodies, verbose output
  and streaming downloads to files.
- `fetch` keeps HTTP out of the networking services: `httpwire` parses bounded
  HTTP responses in the application, while `netd` remains a generic transport.
- Launch capability capacity grows from 7 to 10 grants so commands such as
  `dnsq` can receive standard streams plus independent UDP/TCP sessions without
  changing the lifecycle wire format.
- Kernel build dependencies now include userspace protocol packages imported by
  the kernel, preventing stale kernel artifacts after shared launch/startup
  protocol changes.

## Network architecture

The native path splits device access, transport and applications by authority:

```text
application
    |
    +-- GRESOLV1 -----------------> resolved
    |                                |
    |                                +-- GUDP1 / GTCP1
    |
    +-- GUDP1 / GTCP1 --------------+
                                     |
                                    netd
                                     |
                                 GNETDRV1
                                     |
                                virtio-net
                                     |
                                  device
```

PID 1 creates and brokers the sessions and shared pools. The driver owns the
device but does not understand IP. `netd` understands the network but owns no
PCI, IRQ or DMA authority. Applications receive private transport or resolver
sessions and never touch packets or the device directly.

`fetch` adds an application-level layer without changing that split:

```text
fetch
  |-- GRESOLV1 -> resolved
  |-- GTCP1 ----> netd
  |-- VFS ------> output file
  `-- httpwire
```

## Validation

The networking validation is deterministic and does not depend on the public
Internet.

A host-side `netpeer` implements the peer needed by the QEMU tests, including
ARP, DHCP, ICMP, UDP, TCP, DNS over UDP and TCP, and HTTP fixtures. The network
gate covers:

- DHCP acquisition, renewal and loss;
- static addressing and runtime tuning reload;
- RFC 5227 probing, defence and conflict handling;
- ARP resolution and timeout behavior;
- ICMP echo over Ethernet and loopback;
- hosts-file and resolver lookups;
- DNS caching, negative answers, EDNS fallback and DNS-over-TCP fallback;
- generic UDP bind/connect/send/receive and loopback;
- TCP client/server operation, retransmission, refusal, reset, FIN/EOF,
  listeners, loopback and TIME_WAIT;
- repeated DNS TCP fallbacks beyond the per-session live endpoint limit;
- direct `dnsq` queries over UDP and TCP, including responses larger than one
  GTCP1 receive slot;
- HTTP GET, HEAD, POST, custom headers, chunked transfer, redirects, numeric
  IPv4 URLs and VFS file output through `fetch`.

Host tests cover the wire protocols, endpoint ownership, TCP state machine,
DNS parser/framing and HTTP framing independently of the VM gate. DNS and
network protocol packages also have fuzz targets.

## Limits

- Networking is IPv4 only. `dnsq` can display AAAA records, but GoOS does not
  send IPv6 traffic.
- Only one supported legacy virtio-net device is used; dynamic multi-NIC
  routing is not implemented.
- IPv4 fragmentation and reassembly are not implemented.
- Broadcast and multicast transmission are intentionally limited; multicast
  DNS is not implemented.
- UDP does not receive ICMP Port Unreachable errors for unbound destination
  ports.
- TCP does not implement SACK, window scaling, timestamps, ECN or urgent-data
  delivery.
- DNSSEC, multicast DNS and persistent DNS-over-TCP connections are not
  implemented.
- Native HTTP supports `http://` only. TLS/HTTPS, HTTP/2, HTTP/3, proxies,
  cookies, authentication and compression are not implemented.
- Linux socket syscalls are not implemented; networking in this release is for
  native GoOS applications and services.
- Network tables, queues, endpoint counts, TCP buffers, resolver state and HTTP
  headers have fixed bounds.
