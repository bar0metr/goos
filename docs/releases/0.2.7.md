# GoOS 0.2.7

Release preparation. The final exact-candidate Proxmox run is pending.

## Native remote administration

Native SSH offers an interactive PTY shell and non-PTY command execution:

```sh
ssh user@GOOS_ADDRESS
ssh -T user@GOOS_ADDRESS uname
ssh -T user@GOOS_ADDRESS 'net status'
ssh -T user@GOOS_ADDRESS 'log -n 5'
```

Exec uses the existing native parser and command grants, with separate stdin,
stdout and stderr streams and the command's exit status. PTY exec and background
`&` in one-shot commands fail. The interactive shell keeps its existing grammar;
`exit` closes the session, and remote `reboot`/`poweroff` drain output and close
SSH before the machine lifecycle completes.

A running `gview`, `gfm` or `edit` receives sequence-ordered resize events without
restart. Foreground startup and later events share a geometry sequence so an
older snapshot cannot replace a newer size. Background jobs receive no resize
authority. Raw exit restores cooked shell input.

Eight native images add bounded administration commands:

```text
head [-n N] FILE
tail [-n N] FILE
grep [-i] PATTERN [FILE]
wc [-l|-w|-c] [FILE]
find PATH [-name NAME]
hexdump FILE
hostname [NAME]
date [-u]
```

Head and tail default to 10 lines. Grep matches plain substrings, and find
matches exact basenames. Grep and wc read stdin without a file argument.
Hostname persists `system.hostname` through a new scoped durable mutation API;
its ASCII label has 1..63 characters and no leading/trailing hyphen. Existing
`config set` semantics remain unchanged. Date prints realtime UTC.

The log builtin adds newest matching record selection and exact structured
filters: `log -n 20`, `log --level warn`, `log --component remoted`, and combined
forms. `log -f` waits for new records without polling, with independent cursors,
ring-overwrite gap handling and Ctrl-C cancellation on local and SSH terminals.

Use `remote keys`, `remote key add "ssh-ed25519 AAAA... comment"` and
`remote key remove SHA256:...` to manage authorized keys. Valid mutations replace
the public-key file and reload policy; failures keep the previous effective set.
The command receives no host private-key authority. File replacement retains
FAT's durability limits rather than claiming a journaled cross-service commit.

Remote release acceptance requires the extended QEMU gate and one final kept
Proxmox VM on the exact candidate SHA. Use disposable client keys, pin the host
key against trusted serial `remote status`, and enable `StrictHostKeyChecking=yes`
for automated SSH. Keep the report, serial log, SHA and artifact hashes as
release evidence. On 2026-10-11, `go test ./...`, `make test-race`, additional
focused race tests, native vet and SSH compatibility host tests passed. The
extended QEMU remote gate passed 210 assertions across two persistent boots.
The network regression passed 207 checks, and console-GUI passed its console,
keyboard, filesystem, file-manager, interrupt, viewer and nested-launch checks.
The exact-candidate Proxmox remote-administration run remains the final
acceptance check; its report is retained outside source history with the SHA
and artifact hashes. Full `test-all` and `release-check` have not been repeated
for this release candidate.

SFTP/SCP, forwarding, POSIX shells/PTYS, IPv6, dynamic linking and Linux networking
syscalls remain outside this scope. See [remote access](../development/remote-access.md)
for setup, limits and command details.
