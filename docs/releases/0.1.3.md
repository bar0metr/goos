# GoOS 0.1.3

This release removes the prototype limits that sat under every layer of the
system before Linux compatibility builds on them. FAT32 is a real filesystem,
RAMFS and the physical memory manager scale with the machine, processes have
virtual-memory regions and demand-zero memory, programs of any size load
lazily from the file they came from, file data moves through shared memory,
and command lines, paths, and kernel tables are bounded by decisions rather
than by the size of the first test that needed them. Linux compatibility is
still not part of it.

## What changed

### FAT32 (ADR 0102)

Files reach the FAT32 maximum of 4 GiB − 1 bytes and directories 65536
entries; 512-byte to 64 KiB clusters and one or two FATs are accepted, with the
BPB validated the way Linux's `fs/fat` validates it. Chain walks are bounded
by the volume's cluster count, so corrupt media ends in a typed error. Writes
are ordered so an interruption leaves only states a checker repairs; FAT
sectors are gathered and written a sector at a time to every copy. Long names,
8.3 aliases (`~1` to `~9`, then hashed), and the Windows NT lower-case flags
round-trip. `make test-storage-stress` runs a model-based workload against a
consistency checker, and the host's `fsck` over volumes this code built.

### RAMFS and physical memory (ADR 0103, ADR 0105)

RAMFS stores file data in pages indexed per node, bounded by configured node
and page limits instead of a 4 KiB file and a tiny node table. The physical
memory manager manages every usable range the firmware reports, above 1 GiB
included, through a direct map; memory below 1 GiB is kept for what must be
there.

### Virtual memory (ADR 0104)

Every process has a region map. Heap, stack, and anonymous memory are
reserved and filled with zeroed pages on first touch, charged to the process
only when touched; the stack has a guard, and faults that no region explains
retire the process with a typed reason. `VMReserve`, `VMMap`, `VMUnmap`,
`VMProtect`, `VMDiscard`, and `VMQuery` manage regions; writable executable
memory is refused.

### Executables (ADR 0106, ADR 0108)

Native images (format version 2) are loaded lazily from their origin: the
system image or an executable object, paged in as the program touches them,
up to 256 MiB. A 3 MiB program on the volume starts in about 0.2 s instead of
3.5 s. PID 1 reads a program from a file without blocking: lifecycle events,
other jobs, and restarts are served while a 12 MiB program loads, and a job
stopped while it loads reports "stopped before it started".

### Bulk I/O (ADR 0107)

Processes create shared memory and pass narrowed copies of its handle. `GVF1`
`ReadInto`, `WriteFrom`, and `FillExecutable`, the backend protocol's
multi-slot runs, and the block protocol's bulk operations move up to 64 KiB to
1 MiB per exchange. A 1 MiB file in `/tmp` moves at about 100 MiB/s instead of
1.4 MiB/s; on the FAT32 volume reads reach about 11 MiB/s and writes about
8 MiB/s.

### Startup ABI, command lines, and paths (ADR 0109, ADR 0110)

The startup object (`GST4`) is bounded by bytes, 64 KiB, not by eight
arguments and four variables; its tables are offsets, so an `execve` can be
built on it. The terminal delivers lines of up to 4096 bytes in parts, the
shell tokenizes by bytes, and `cat`, `rm`, `touch`, and `mkdir` take any
number of paths. One contract holds everywhere: 255-byte names, 4096-byte
paths; longer ones are refused as "file name too long", and paths too long
for a message travel in an attached object.

### Registries and errors (ADR 0111)

Kernel registries hold pointers and take an entry's pages when it is created:
256 channels, 256 streams, 256 shared-memory objects, 64 executable objects,
256 handles per process, 64-object `WaitAny`. The shell has eight job slots,
and the VFS serves 63 sessions with 256 open files. Filesystem errors keep
their reason: no space, corrupt, timeout, peer died, unsupported, and name too
long are distinct native statuses.

## Limits

| Limit | Value | Where |
| --- | --- | --- |
| file (FAT32) | 4 GiB − 1 | FAT32 itself |
| directory (FAT32) | 65536 entries | FAT32 itself |
| file (RAMFS) | page limit of the instance | `ramfs.Limits` |
| name / path | 255 / 4096 bytes | `limits.NameMax`, `limits.PathMax` |
| command line | 4096 bytes | `tty.MaxLine` |
| startup object | 64 KiB, strings 32 KiB, 64 handles | `kcall.MaxStartupSize` |
| executable | 256 MiB | `executable.MaxSize` |
| shared-memory object | 256 MiB, 16 per process | `shmem.MaxPages` |
| process page quota | 32 MiB (PID 1 64 MiB) | `process` quotas |
| tasks, processes | 64 | scheduler masks (ADR 0111) |
| channels, streams | 256 each | `ipc.MaxChannels`, `stream.MaxStreams` |
| background jobs | 7 | `exec.Slots` − 1 |

## Known limitations

- FAT32 names are printable ASCII; on-disk names with other characters show
  their 8.3 alias. The FSInfo free count is written as "unknown", which
  `fsck_msdos` reports as a warning.
- There is no journal: an interrupted write leaves states `fsck` repairs.
- A FAT32 node is named by where its directory entry is, so a file open
  across a rename into another directory must be opened again.
- Tasks and processes stay at 64 until the scheduler's masks are widened.
- A process's page tables are freed when it exits, not when a region is
  unmapped.
- The kernel occupies the low GiB and native images are linked at fixed
  addresses, so address-space layout randomization is still future work.
- The terminal's redraw assumes a line fits one row of the console.

## Validation

`make release-check` runs the reproducible build, lint, documentation checks,
unit, integration, and security tests, the FAT32 storage stress test, the
boot test (386 checks, including multi-megabyte programs and files on the
volume, 700-argument commands, 255-byte names, seven concurrent pipelines, and
a leak check that repeats a workload and requires the same pages in use), and
the stress run.
