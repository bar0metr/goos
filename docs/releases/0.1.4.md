# GoOS 0.1.4

GoOS 0.1.4 completes the native storage and execution base required before
Linux ELF compatibility. The release keeps FAT32, VFS, block I/O, and the
virtio-blk driver in userspace. It adds interoperable FAT32 metadata, bounded
partition slices, native checking and repair, stable open objects, isolated
high-half kernel entry, file-backed executable pages, and launch resource
profiles.

## FAT32

The FAT32 service accepts logical sectors of 512, 1024, 2048, and 4096 bytes.
It accepts sectors-per-cluster values from 1 through 128 when the resulting
cluster size and FAT32 cluster count are valid. One-FAT and two-FAT volumes
work; mirrored copies stay synchronized, while a volume that selects one active
FAT reads and updates that copy.

VFAT long names decode and encode UTF-16LE, including surrogate pairs, into
UTF-8. The native namespace accepts 1024-byte components while FAT32 enforces
the on-disk limit of 255 UTF-16 units. Tests cover Cyrillic, CJK, emoji,
combining characters, mixed scripts, malformed sequences, alias collisions,
and valid foreign trailing-dot names.

The service decodes and encodes FAT creation, modification, and access dates,
including the two-second modification-time field and creation tenths. It keeps
read-only, hidden, system, archive, directory, and volume-label attributes.
FSInfo signatures, free count, and next-free hints are validated and maintained
in both copies. A valid backup boot sector can supply a damaged primary for a
read-only mount; repair mode can restore either copy from the valid one.

The largest tested file is 4 GiB minus one byte on a sparse stress volume. The
largest directory workload creates 8000 long names, which occupy 32000 FAT
directory entries. Fragmented files, disk-full rollback, truncate growth and
shrink, cross-directory moves, and allocation reuse have deterministic tests.

The interoperability suite creates volumes with `newfs_msdos` on macOS or
`mkfs.fat` on Linux, modifies them through GoOS, and checks them with
`fsck_msdos` or `fsck.fat`. It also checks GoOS-formatted volumes with host
tools. Stored foreign fixtures keep the parsing cases available on hosts that
lack those programs.

## Partitions and mounts

The block service detects a FAT32 superfloppy or parses MBR and GPT. MBR
support includes primary entries and bounded EBR chains; logical partitions
use indices starting at five. The extended container remains visible but
cannot be selected as a filesystem volume. GPT validates both headers, entry
array CRC-32, usable ranges, entry sizes, overlaps, and backup placement. A
valid backup can replace an invalid primary for selection without rewriting
the table.

PID 1 gives the filesystem service a block endpoint restricted to the selected
slice. Every request checks overflow and slice bounds before it reaches the
driver. Raw, MBR, GPT, read-only, out-of-range, overlapping, bad-CRC, and
truncated-table cases have host and boot tests.

VFS can mount, unmount, and remount a backend at runtime. Unmount flushes dirty
data and refuses while an open handle still names the mount. The block service
re-resolves the selector when PID 1 attaches a replacement filesystem service.

## Native FAT32 checking and repair

`fsck-fat --check auto` checks boot metadata, FAT copies, FSInfo, bounded
chains, loops, cross-links, chain length, lost clusters, directories, dot
entries, LFN sequence and checksum, duplicate aliases, attributes, and empty
file ownership. PID 1 unmounts the filesystem first and grants the checker a
read-only endpoint for the selected slice.

`fsck-fat --repair auto` receives an exclusive writable endpoint after the
same unmount. It restores boot metadata from a valid peer, synchronizes FAT
copies, removes invalid or orphan LFN slots, detaches empty-file chains, trims
chains beyond EOF, reclaims proven lost clusters, and rewrites FSInfo. A second
repair pass makes no changes.

Repair leaves cross-linked live files, short live chains, unreadable
directories, and other ownership ambiguities unchanged. It reports them and
suppresses lost-cluster reclamation when the namespace walk cannot prove
ownership.

## Stable file identity

FAT32 uses generation-checked open-object cookies instead of directory-entry
locations. An open handle continues to name the same file after rename or a
move to another directory. Several handles may share the object until the last
close.

GoOS refuses unlink of an open FAT32 file. Unlink succeeds after the last close.
This release does not implement deferred delete-while-open semantics. Service
restart invalidates open cookies; callers reopen paths after PID 1 restores the
mount.

## Memory layout

Earlier process page tables retained the low kernel mapping, which occupied
ordinary ELF addresses such as `0x00400000`. Process roots now contain only
supervisor-only high entry and return trampolines, transition metadata, the
current task's high kernel stack, and the direct-map slot. The trampoline loads
the kernel CR3 before entering low-linked TinyGo code. No Go code executes
through a high alias.

Native test images execute at `0x00402000`; the loader accepts normal low user
addresses and still rejects overlap, arithmetic wrap, W+X segments, and entry
points outside executable segments. Ring 3 cannot read the high transition
pages. The kernel remains low-linked and non-relocatable; this release isolates
process roots rather than claiming a fully relocated kernel.

## Executables

The old VFS launch path copied the complete file into kernel-owned executable
pages before the loader could start. PID 1 now prepares one sealed 4 KiB header
page and converts the VFS session into a pathname-independent executable-source
capability. The loader validates the header and records lazy image regions.
Page faults request file offsets through the pinned open object; BSS stays
demand-zero.

A source reserves one header frame and one page-list index before launch.
Payload memory grows only for pages the process touches and counts against that
process's page quota. The boot test starts a padded 12 MiB image without reading
its untouched padding. Writes, truncation, and unlink remain blocked while the
source exists; rename works.

## Launch resource profiles

PID 1 selects one of three kernel-defined profiles:

| Profile | Channels | Streams | Tasks | Pages |
| --- | ---: | ---: | ---: | ---: |
| `tiny` | 2 | 8 | 1 | 2048 |
| `normal` | 4 | 16 | 4 | 8192 |
| `large` | 8 | 32 | 8 | 16384 |

Commands and services default to `normal`. The `quota` diagnostic uses `tiny`;
`fsck-fat` and `vmprobe` use `large`. PID 1 sends a profile identifier, never
numeric limits. The kernel owns the table and rejects unknown identifiers.
Children cannot raise their limits. `ProcessInfo` and `quota` expose the
applied limits. PID 1 retains its separate bounded system quota.

## Remaining limitations

- The kernel image remains low-linked and non-relocatable. High assembly
  trampolines isolate it from process roots.
- FAT32 has no journal. Ordered writes and native repair contain interrupted
  updates but do not make multi-step changes atomic.
- Repair does not choose an owner for cross-linked live files or invent bytes
  for a short live chain.
- Unlink of an open FAT32 file is refused; delete-while-open is absent.
- A filesystem-service restart invalidates open-object cookies and executable
  sources that still depend on that service.
- Native executables use fixed addresses and have no executable ASLR.
- CPU use is accounted in timer ticks but has no throttling policy.
- The terminal redraw assumes the edited line fits one console row.

## Validation

`make release-check` builds the ISO twice from clean trees and compares every
artifact. It then runs lint, documentation checks, unit, integration, security,
storage stress, ISO checks, the QEMU boot suite, and the QEMU stress matrix.
Performance measurements remain reports because host load changes their timing.
