# GoOS 0.1.2 (in progress)

This release is not finished. It prepares the storage path for Linux
compatibility: programs run from the persistent volume, file data will move
through shared memory instead of IPC payloads, and the VFS will be able to
restart. This file grows with each change and becomes the release notes when
0.1.2 is released.

## What changed

### Programs run from the filesystem (ADR 0097)

A command word with a slash is a program path: `/home/demo/args`, or `./args`
relative to the working directory. Under `/system` PID 1 looks in the system
image as before. Anywhere else it reads the file through the VFS into an
executable object, kernel memory that no process maps and that seals itself
when its last byte is written, and names the sealed object in the launch
request. The kernel validates the bytes as a native image exactly as it does
the image's, and still resolves no path.

Only PID 1 can create an executable object: its loader capability is not
transferable. A program read from the filesystem receives its standard streams
and no other grant, whatever its name. A file that is not a regular file of at
most 1 MiB, or whose size changes while it is read, is refused; so is a path
in `/system` outside `/system/bin`, which holds services rather than commands.

Two native operations are added, `ExecutableCreate` (37) and `ExecutableWrite`
(38). The exec protocol between the shell and PID 1 is version 10: a stage may
name any canonical absolute path. The lifecycle launch request is unchanged.

Under QEMU TCG a 22 KiB program starts from `/home` in about 113 ms, against
14 ms from `/system/bin`: PID 1 reads the file 224 bytes per exchange. Launches
from the system image are unchanged.

### Fixes

- Open files in the VFS belonged to no one: any session could use a handle
  another had opened, one session could fill the whole table of 64, and the
  files a crashed process left open stayed open. Each file now belongs to the
  session that opened it, a session holds at most 16, and they close when the
  session goes.
- `ls` and `stat` exhausted their memory on a large directory or tree, as
  `cp` did on a large file; they now reuse it for each entry.
- `cp` stopped after a few hundred bytes of a larger file, exhausting its
  memory, and left the target truncated. It now copies files of any size.

## Known limitations

Everything listed for 0.1.1 still holds, except that programs are no longer
limited to the system image. In addition:

- A program is read from its file on every launch, one IPC exchange per 224
  bytes; a 22 KiB program takes about a hundred.
- A program on a filesystem is at most 1 MiB.
- PID 1 reads a program before it answers anything else, so a large program
  on a slow volume delays other launches and supervision for as long as the
  read takes.
- A file rewritten at the same size while it is being read can launch as a
  mixture of both versions. It is validated either way and runs with its
  standard streams only.
