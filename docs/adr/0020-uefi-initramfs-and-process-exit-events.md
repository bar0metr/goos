# ADR 0020: UEFI initramfs and process exit events

## Status

Accepted

## Decision

The bootstrap UEFI application reads a bounded `initramfs.tar` from its own EFI
filesystem before `ExitBootServices`. Firmware-allocated loader pages preserve
the archive across handoff and remain outside the usable PMM pool. The archive
is strict USTAR generated by a repository tool with fixed metadata; the kernel
parser accepts bounded regular files and directories and validates checksums.

Init is discovered as `system/init`, validated by the native image loader,
loaded into a distinct address space, registered as process ID 1, and scheduled
at ring 3. Native exit and userspace fault paths record task termination in
bounded architecture storage. The process registry converts the last Task exit
into one process exit event consumed by supervision policy.

## Consequences

PID 1 now originates in the built initramfs rather than a kernel byte array.
The build is independent of host tar metadata. Process death has one bounded,
typed path for normal exits and CPU faults. The bootstrap init image currently
announces itself and remains runnable; moving the supervisor event loop and
service launches fully into PID 1 requires lifecycle IPC and is the next step.
